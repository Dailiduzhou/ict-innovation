## 一、ICT 创新赛 · 赛题一（第十一届 2026–2027）

### 1.1 技术强制项（**资格红线**）

> 规则原文：**"未采用赛题要求的华为技术的队伍不符合参赛资格。"**

| # | 强制项 | 落地方式 | 证据 |
|:--:|---|---|---|
| M1 | 使用**华为云码道 CodeArts 代码智能体**开发 | 全队统一用 CodeArts | 开发录屏 / 会话记录 |
| M2 | 基于已有**智能体和 Skills** 快速开通关联服务、部署 | 先验证官方已有能力，再按项目需要扩展 | 实际导入／调用、创建／关联与部署记录；不是只交两个自定义 Skill |
| M3 | 开通关联 **RDS、Redis** 等华为云服务 | RDS 业务事实；Redis 辅助，不作唯一任务账本 | 实际创建关联与读写，KooCLI 只是可选工程手段 |
| M4 | **部署在华为云，作品可在线运行** | ECS + 公网 EIP | **公网可访问 URL** |
| M5 | 入围总决赛的作品**需开源** | 推 Gitee / GitHub | 仓库地址 |

> 本地 Demo 不替代云上部署；官网还要求可视化展示。KooCLI、两个自定义 Skill、OpenHarmony、IoTDA 或技术覆盖数量不是独立公开必选指标。当前产品以手机全双工、并行 Agent、可靠记忆与家庭连接为核心，硬件可选，不由资格规则强推。
>
> **2026-12-01 是既有内部首次上云目标**，既有核查记录中的官网正文没有把它列为独立截止。实际材料提交日期需以组委会通知确认。

| 阶段 | 官方评分构成 |

| 初赛 | 创新性 60%、应用价值 40% |

## 二、大创 · 创业训练项目

### 2.1 项目类型对照

| 类型 | 产出 |
|---|---|
| 创新训练项目 | 研究报告 / 学术论文 / 专利 |
| **创业训练项目** ← 本项目 | **商业计划书 / 可行性研究 / 企业模拟运行 / 创业报告** |
| 创业实践项目 | 实际创业与运营；申请主体、注册和实践条件按当年学校／主管部门通知确认，不以旧稿一句话替代资格审核 |

### 2.2 政策与年度通知

老年生活辅助与家庭连接可以作为社会需求背景，但不能仅据“养老＋健康”就宣称符合某项重点支持或医学定位。正式申报前补齐当年教育主管部门与学校通知的官方来源、适用条款和引用范围，不沿用旧稿缺少来源的政策引文。

2027 年度通知、校内预申报、创业训练格式和立项时间需分别核实；旧稿“预计 3 月”只是准备窗口，不是确认的年度发布承诺。

### 2.3 创业训练还缺什么

商业计划书需回答 **谁付钱／持续使用理由／可触达市场／凭什么赢／成本是否可承受**。当前产品假设与商业边界见 [01](01-定位与边界.md)，不得以子女愧疚感或老龄人口总量直接替代支付与市场证据。

## 三、双轨包装：一个内核，两种材料

| 维度 | ICT 创新赛（赛题一） | 大创（创业训练） |
|---|---|---|
| 核心考核 | 创新性 60% + 可运行系统 + 商用落地潜力 | 商业计划书 + 可行性研究 + 团队分工 |
| 必须有 | CodeArts 开发 + 云上部署 + 在线可运行 | 指导教师、商业计划书、企业模拟运行记录 |
| 交付 | 代码 + demo 视频 + 答辩 PPT + 开源仓库 | 商业计划书 / 可行性研究报告 / 创业报告 |
| 侧重 | **"做出来了什么"**（系统、创新点、演示） | **"为什么值得做"**（需求、竞争、模式、可行性） |

> 用户访谈与可用性测试（`10`）两边都要用——它既是商业计划书的「需求验证」证据，
> 也支撑 ICT 赛的「商用落地潜力」。
