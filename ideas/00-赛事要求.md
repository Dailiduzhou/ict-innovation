## 一、ICT 创新赛 · 赛题一（第十一届 2026–2027）

### 1.1 技术强制项（**资格红线**）

> 规则原文：**"未采用赛题要求的华为技术的队伍不符合参赛资格。"**

| # | 强制项 | 落地方式 | 证据 |
|:--:|---|---|---|
| M1 | 使用**华为云码道 CodeArts 代码智能体**开发 | 全队统一用 CodeArts | 开发录屏 / 会话记录 |
| M2 | 基于已有**智能体和 Skills** | 用 CodeArts 的 Skill 机制沉淀领域知识 | Skill 配置文件 |
| M3 | 关联 **RDS、Redis** 等华为云服务 | RDS 存结构化数据；Redis 存会话/缓存/限流 | 架构图 + KooCLI 创建记录 |
| M4 | **部署在华为云，作品可在线运行** | ECS + 公网 EIP | **公网可访问 URL** |
| M5 | 入围总决赛的作品**需开源** | 推 Gitee / GitHub | 仓库地址 |

> ⚠️ **M4 最容易被低估**：本地 `npm run dev` 不算数，必须有在线地址。

### 1.2 其他硬规则

| # | 规则 | 影响 |
|:--:|---|---|
| R2 | **3 名学生 + 1 名指导教师，须同一所高校** | ✅ 已确认满足 |
| R3 | 报名成功后**不得更换**队员与指导教师 | 组队已定 |
| R4 | 每名选手**只能报一个赛道** | 全队避免同时打实践赛 |
| R5 | **代码无法复现 PPT 展示效果 → 取消资格** | 演示只放已实现功能；**mock 必须在 UI/PPT/代码三处自证**（见 `07` §一） |
| R7 | 禁止把其他赛事作品**不加改进**地重复参赛 | 大创与 ICT 材料须有实质差异（§三） |

### 1.3 时间线

| 节点 | 时间 |
|---|---|
| **报名截止** | **2026-11-30** |
| 初赛（线上提交材料） | 2026-12 |
| 中国总决赛（材料 + 演示答辩） | 2027-03 |
| 全球总决赛（深圳，线下） | 2027-05 |

> ✅ **当前无校内预报名**，直接按国家赛程推进。

### 1.4 评分侧重

- **创新性占 60%**（初赛）/ 40%（中国区总决赛、全球总决赛）
- 官方建议原话：*"从小切口入手，打造能实际运行的系统，优于宏大的概念设计"*

## 二、大创 · 创业训练项目

### 2.1 项目类型对照

| 类型 | 产出 |
|---|---|
| 创新训练项目 | 研究报告 / 学术论文 / 专利 |
| **创业训练项目** ← 本项目 | **商业计划书 / 可行性研究 / 企业模拟运行 / 创业报告** |
| 创业实践项目 | 实际注册公司、真实运营（**未注册公司，不可报**） |

### 2.2 政策口径（对本项目有利）

教育部《关于开展国家级大学生创新训练计划立项和结题验收工作的通知》：

> 重点支持项目"面向世界科技前沿、面向经济主战场、**面向国家重大需求**、**面向人民生命健康**"，
> 鼓励围绕基础学科以及**新工科、新医科**、新农科、新文科等关键领域开展创新实践。

**养老 + 健康属于"面向人民生命健康"**，是大创重点支持方向，申报书应明确对应此条款。

> ⚠️ 国家级立项通知通常**每年 3 月**发布，各校预申报多在 3–5 月。2027 年度项目需在 2027 春季前完成选题打磨。

### 2.3 创业训练还缺什么

商业计划书需要 **谁付钱 / 市场多大 / 凭什么赢** 三问，当前仅部分具备（见 `01` §六）。

## 三、双轨包装：一个内核，两种材料

| 维度 | ICT 创新赛（赛题一） | 大创（创业训练） |
|---|---|---|
| 核心考核 | 创新性 60% + 可运行系统 + 商用落地潜力 | 商业计划书 + 可行性研究 + 团队分工 |
| 必须有 | CodeArts 开发 + 云上部署 + 在线可运行 | 指导教师、商业计划书、企业模拟运行记录 |
| 交付 | 代码 + demo 视频 + 答辩 PPT + 开源仓库 | 商业计划书 / 可行性研究报告 / 创业报告 |
| 侧重 | **"做出来了什么"**（系统、创新点、演示） | **"为什么值得做"**（需求、竞争、模式、可行性） |

> 用户访谈与可用性测试（`10`）两边都要用——它既是商业计划书的「需求验证」证据，
> 也支撑 ICT 赛的「商用落地潜力」。
