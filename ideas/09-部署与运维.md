## 一、为什么用 KooCLI

**KooCLI**（华为云命令行工具服务，原名 HCloud CLI）是为**发布在 API Explorer 上的云服务 API** 提供的命令行管理工具。

| 理由 | 说明 |
|---|---|
| **透明可评审** | 一条条命令都在脚本里，评审看得懂；比控制台截图可信 |
| **可复现** | 换机器/账号跑同一个脚本能重建环境 |
| **可演示** | 答辩现场跑"一键部署"比讲架构图有说服力 |
| **与赛题相关** | 赛题一考"华为云产品"，KooCLI 本身就是华为云产品线的一员 |
| **幂等可控** | 先查后建，重复执行不重复花钱 |

**不推荐**：应用运行时 shell out 调 `hcloud`（用 SDK）；长期 IaC 状态管理（用 RFS 或 Terraform，列入二期）。

## 二、部署拓扑

```
cn-north-4
├── VPC            vpc-ageguard            10.0.0.0/16      不计费
│   ├── Subnet     subnet-ageguard-app     10.0.1.0/24      不计费
│   └── Subnet     subnet-ageguard-data    10.0.2.0/24      不计费
├── SecurityGroup  sg-ageguard-app         80/443 全网；22 仅管理 IP
├── SecurityGroup  sg-ageguard-data        3306/6379 仅来自 sg-app
├── ECS            ecs-ageguard-app        最小规格                ★计费
│   └── EIP        公网地址                ← M4 的载体           ★计费
├── RDS            rds-ageguard            MySQL 8.0 / PG 最小规格 ★计费
├── DCS (Redis)    redis-ageguard          单机最小规格           ★计费
└── OBS            obs-ageguard-audit      审计归档（可选）        ★计费

另有（不在本项目 VPC 内）：
  MaaS（华为云 MaaS 服务）—— 仅"西南-贵阳一"，跨区调用需实测延迟
```

### 创建顺序（依赖关系，**不能乱**）

```
1. IAM 子账号 + AK/SK          ← 先建，后面全用它
2. VPC
3. Subnet (app / data)
4. SecurityGroup + 规则
5. RDS                         ← 依赖 subnet-data + sg-data
6. DCS Redis                   ← 依赖 subnet-data + sg-data
7. ECS                         ← 依赖 subnet-app + sg-app
8. EIP + 绑定 ECS
9. 部署应用（迁移 + 起服务）
10. OBS（可选）
```

**基础可见性检查**：公网可打开登录页；正式音频与业务入口使用有效 HTTPS。这不等于部署验收通过。

**完整验收**：资源创建／关联、应用镜像或产物传递、密钥注入、数据库迁移、RDS／Redis 实际读写、设备上下行、健康检查、失败恢复、重复执行与清理；另一个成员按说明复现。只执行实例查询或看到登录页，不证明整条链路已实现。

## 三、工具获取：**不预置到项目**

**KooCLI 与官方 devkit 由 Agent 在运行时获取，不 commit 进仓库。**

| 做 | 不做 |
|---|---|
| ✅ `deploy/` 脚本只假设 `hcloud` 在 PATH 中 | ❌ 把 `hcloud` 二进制/安装包 commit 进仓库 |
| ✅ 在 README / 部署文档写清前置条件与获取命令 | ❌ 把 `huaweicloud-devkit` 写进 `package.json` / `requirements.txt` |
| ✅ 脚本开头 `command -v hcloud \|\| die` 并提示获取方式 | ❌ 在 `.agents/` 里预置官方 skill 副本 |

**好处**：仓库干净；赛题一 M5 开源时不用清理第三方代码；工具版本不会跟仓库一起陈旧。

**获取命令（Agent 运行时执行）：**

```bash
# 方式 1：官方一键脚本（Linux / macOS）
curl -sSL https://cn-north-4-hdn-koocli.obs.cn-north-4.myhuaweicloud.com/cli/latest/hcloud_install.sh \
  -o ./hcloud_install.sh && bash ./hcloud_install.sh

# 方式 2：官方 DevKit（附带 skills + 安全护栏 + 凭证脱敏）
npx --yes huaweicloud-devkit install --target codearts   # 装到 Agent 侧
npx --yes huaweicloud-devkit install-hcloud              # 装 KooCLI
npx --yes huaweicloud-devkit auth init                   # 同步 AK/SK

hcloud --version    # 验证
```

**平台支持**：Linux（AMD64/ARM64）、macOS（AMD64/ARM64）、Windows、Docker ✅；
**无 HarmonyOS / Android / iOS 本机支持**（KooCLI 是桌面/服务器 CLI，与移动客户端无关）。
**依赖**：KooCLI 自带运行时，不需预装 Java/Python。

## 四、三条铁律

| # | 铁律 |
|:--:|---|
| 1 | **AK/SK 绝不进代码/脚本/`.env`/git/聊天记录**。赛题一 M5 要求开源，一旦写进代码就会公开 |
| 2 | **所有写操作先 `--dryrun`**。打印请求报文但不真正调用 API |
| 3 | **不凭记忆写 operation 名**。一律 `hcloud <SERVICE> --help` 现场确认 |

### 命令发现四步法

```bash
hcloud --help                                  # ① 列出所有可用 SERVICE
hcloud RDS --help                              # ② 列出该服务的 operation
hcloud RDS ListInstances --help                # ③ 查看参数与帮助
hcloud RDS CreateConfiguration --cli-region="cn-north-4" --skeleton   # ④ 生成入参骨架
```

**排错首选组合**：`--debug`（打印完整请求 URL）+ `--dryrun`（校验不执行）。
**部署脚本必须用 `--cli-waiter`**——RDS/Redis/ECS 创建都是异步的，不等就绪就进入下一步必然失败。

## 五、⚠️ CodeArts 沙箱陷阱

赛题一**强制使用 CodeArts 代码智能体**开发，但：

> **CodeArts Agent 默认开启沙箱模式，会直接拦截 KooCLI。**
> （官方 DevKit README 原文：*"CodeArts defaults to sandbox mode which blocks KooCLI"*）

**解法（二选一）：**
1. 在**沙箱外的终端**安装 KooCLI，Agent 只调用已安装的 `hcloud`
2. 关闭沙箱：CodeArts 设置 → `Chats` → `Agents Terminal Command Running Mode` → `Auto Running`

> ⚠️ **与"不预置工具"直接相关**：既然不预置，Agent 就必须在运行时**能装上**。
> **开工第一周就要验证**（`12` T-10 / R-18），别拖到部署那天。

## 六、凭证策略（三层）

| 用途 | 用什么 | 存哪 |
|---|---|---|
| 本地开发（人） | 子账号 AKSK | `hcloud` profile（本地，**不提交**） |
| CI / 部署脚本 | 子账号 AKSK | **环境变量**，CI secret 注入 |
| **ECS 运行态** | **`ecsAgency` 委托** | **什么都不存** ⭐ |

> ⭐ **演示期结束前把部署脚本从 AKSK 切到 `ecsAgency`**。
> 这在答辩里是一个**可演示的安全加分点**："我们的服务器上不存在任何长期密钥。"

**避免 shell history 泄露**：

```bash
export HISTCONTROL=ignorespace    # 以空格开头的命令不进 history
# 然后： <空格>hcloud configure set --cli-access-key=...
```

**IAM 最小权限**：按角色建子账号（`ageguard-deploy` / `ageguard-ci` / `ageguard-readonly`），
只授予业务必需的区域与动作，**不授予 `Delete*`**（部署脚本一般不需要）。
详见 `references/credential-security.md`。

**其他 API Key**：
- MaaS API Key（`11` §五）
- 百炼 API Key —— 官方明确要求**只存 AppServer，不写客户端**，客户端走后端中转
