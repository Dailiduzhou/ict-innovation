## 二、Qwen-Audio 实时语音：本轮文档支持

来源：[官方实时语音指南](https://help.aliyun.com/zh/model-studio/qwen-audio-realtime-user-guides)。

| 核查维度 | 正文支持 | 不能外推 |
|---|---|---|
| 模型／协议 | 指南以 `qwen-audio-3.1-realtime-plus` 为示例；介绍 WebSocket、AOQ、WebRTC | 各协议在本项目手机框架下都已可用 |
| Python | 有原生 WebSocket Python 示例，使用 `websockets` 等依赖 | 示例等于完整官方原生 SDK，或已验证 `dashscope` 某版本全部实时 API |
| 交互 | `server_vad`、`smart_turn`、手动控制；双向流式音频／文本 | 所有老人口语都自然、没有误打断或漏听 |
| 工具与搜索 | 支持 Function Calling；指南说明内置联网搜索不能与 FC 同时启用 | 所有工具调用可靠、所有模型或供应商都具有同样限制 |
| 会话上下文 | 表列音频最多 50 轮、累计保留音频 300 秒；默认轮次与可调上限有区别，较早历史会丢弃 | 供应商会话上下文就是跨会话长期记忆；300 秒也不是本项目已定会话时长上限 |
| 音频格式 | 所查 WebSocket 路径输入 PCM 16kHz／16bit／单声道，输出 PCM 24kHz／16bit／单声道 | 全部协议／未来版本都固定相同格式 |

**项目结论**：作为优先 PoC 候选。必须自建可靠个人记忆，不能依赖供应商保留历史。AOQ／手机端 SDK 的语言、临时凭证、转写事件与断线恢复另核；不把 Python 示例当手机 SDK。

旧稿的 `dashscope` 最低版本、`fun_realtime` 结构、固定价格与成本估算不作为当前锁定依据。采用时重新核对模型、地域、接口、依赖版本、数据政策与账单，不用文档单价推定真实每小时成本。

## 三、MaaS 标准 API V2：本轮文档支持

来源：[官方标准 API V2](https://support.huaweicloud.com/model-call-maas/model-call-019.html)、[历史开通条件来源](https://support.huaweicloud.com/model-call-maas/model-call-052.html)。

- 所查 API 为 HTTP `/v2/chat/completions`，Bearer Key，提供 Python `requests` 与 curl 示例。HTTP 可调不等于已经确认某 Python 原生 SDK。
- 正文列出 openPangu 等模型，所列支持地域为西南－贵阳一；不将该表外推整个云平台的永久区域限制。
- 有流式结果、工具调用字段和缓存用量等参数；具体模型支持不同，必须查表并实测。
- 所查 openPangu 支持 `tool_choice=none/auto`，思考开关支持 enabled／disabled；不能只据参数表断言已满足所有业务工具。
- 官方提醒工具参数可能不是有效 JSON，或包含 schema 外参数；执行前必须校验。
- 示例包含 `verify=False` 等调试写法，项目不得照搬；TLS 校验、超时、Key 注入和日志脱敏按生产安全要求实现。

**项目结论**：作为 Agent 推理候选，不用于证明语音全双工、业务自治安全或实时响应已达标。实际开通、委托、Key 作用域、可关闭性、费用、缓存效果与代金券均在 T-26～30／51／52／71 实测或复核。

## 六、运动健康与 NearLink：条件性资料

- Health Service Kit 的 HarmonyOS 指南有 ArkTS 路径；旧 Android Codelab 有 Java 示例，另有 REST 介绍。各路径、账号、设备和指标不能混用，REST 存在不证明 Python／Node.js 原生 SDK。
- 原核查的 HarmonyOS 表中活动、心率等标注小时级，部分指标分钟级；等级需看渲染图标，不外推所有路径。高阶数据与主体资质、审批和用户授权分别相关。
- 个人／企业／事业单位的准入不同，学校主体不由学生身份自动获得；数据时效不支持可靠实时监护主张。
- 原 Health Industry SDK 资料涉及平台分支、行业设备与固件、测量间隔，不能把消费型号名称或 HRV 接口当任意设备连续可读。
- 所查手机侧 NearLink Kit 为 HarmonyOS／ArkTS 通信能力；它不提供人物、健康或业务语义，不把这一手机接口范围外推为整个星闪生态只有一种语言。

来源：[Health 数据](https://developer.huawei.com/consumer/cn/doc/doccenter-capabilities/health-data-overview)、[资格](https://developer.huawei.com/consumer/cn/doc/doccenter-capabilities/health-application-qualifications)、[申请](https://developer.huawei.com/consumer/cn/doc/doccenter-capabilities/health-apply)、[采样](https://developer.huawei.com/consumer/cn/doc/doccenter-capabilities/health-samplepoint-manage)、[Android Java](https://developer.huawei.com/consumer/cn/codelab/HUAWEIHealth-DevEco/)、[REST](https://developer.huawei.com/consumer/en/doc/HMSCore-Guides/overview-restful-api-0000001050071695)、[行业 SDK](https://developer.huawei.com/consumer/cn/doc/huaweihealth-Guides/introduction-0000002372172841)、[行业设备](https://developer.huawei.com/consumer/cn/doc/huaweihealth-Guides/supported-devices-0000002478417006)、[NearLink SSAP](https://developer.huawei.com/consumer/cn/doc/doccenter-capabilities/nearlink-ssap-server-connect)、[NearLink FAQ](https://developer.huawei.com/consumer/cn/doc/harmonyos-guides/nearlink-faq)、[手机硬件要求](https://consumer.huawei.com/cn/support/content/zh-cn15951818/)、[OpenHarmony 组件](https://github.com/openharmony/communication_nearlink_service)。
