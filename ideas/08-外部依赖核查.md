## 一、速览

| 依赖 | 结论 | 定性 |
|---|:--:|---|
| **NearLink 星闪** | 仅 HarmonyOS（ArkTS），只给通信能力，无业务语义；手机支持取决于硬件型号 | ⚠️ 受限 |
| **Health Service Kit** | 无面向第三方的"穿戴 SDK"；数据来自运动健康 App 数据集；心率**小时级**；高阶数据需企业账号 | ⚠️ 受限 |
| **智能家居数据** | HarmonyOS Connect 面向设备商/模组商/芯片商，无第三方 App 数据 API | ❌ 不可得 |
| 老人自述 / 问卷 / AI 闲聊 | 无外部依赖 | ✅ 可行 |
| **推送（HMS Push）** | 只覆盖华为设备；**荣耀需独立通道**；小米等要求上架 | ⚠️ 受限 |
| **端到端实时语音** | Qwen / 豆包可用；**华为云无对等产品** | ✅ 第三方可用 |
| **Agent 搜索 API** | 博查（国内，专为 LLM 设计，免费 1000 次）；Tavily 为海外备选 | ✅ 可行 |
| **华为云（CodeArts/RDS/Redis/MaaS）** | 成熟产品，学生可用，报名后发代金券 | ✅ 可行 |

**一句话**：数据来源的三条 IoT 线里，只有"老人自述 + AI 闲聊"在一期真正可实现。

## 二、NearLink Kit（星闪服务）

| 项目 | 结论 |
|---|---|
| 支持语言/平台 | **HarmonyOS（ArkTS / ArkUI）**；**无 Android / iOS / Web SDK** |
| 提供的能力 | 设备发现（扫描/广播）、连接管理、**SSAP** 数据传输、端口数据传输、属性读/写/通知 |
| **不提供** | 任何业务/语义能力（无位置、无行为识别、无健康数据）——它只是**一条链路** |
| 硬件要求 | 手机需**硬件支持**；官网明确"星闪与具体硬件支持能力有关，**无法通过系统升级支持**" |
| 约束 | 连续 `writeData` 会拥塞发送队列；官方建议**发送间隔 10ms** |

**定性**：星闪 = **自研硬件终端与手机之间的通信方式**，仅此而已。
不是任何赛题的技术要求，对报名资格零帮助。保留为 `TransportChannel` 端口的预留实现（`07` §三）。

## 三、Health Service Kit（运动健康服务）

### 3.1 架构事实（关键）

```
华为穿戴设备 / 血压计 / 体脂秤
        │ （蓝牙）
        ▼
   华为运动健康 App          ← 数据在这里聚合
        │ （用户授权 + 华为账号）
        ▼
   Health Service Kit API    ← 第三方应用只能到这里
```

**我们拿到的不是传感器原始数据，而是"华为运动健康 App 里已聚合的数据集"。**

### 3.2 数据项与时效性（官方《数据开放总览》）

| 数据子类 | 数据项 | 及时性 |
|---|---|:--:|
| 日常活动 | 步数、热量、距离 | 小时级 |
| **心率** | 动态心率、静息心率、**心率变异性（HRV）** | **小时级** |
| 血氧 | 瞬时血氧饱和度 | 小时级 |
| 压力 | 压力得分 | 小时级 |
| 体温 | 体温、皮肤体温 | 分钟级 |
| **血压** | 收缩压、舒张压、脉搏 | 分钟级 |
| 体重 | 体重、体脂、BMI | 分钟级 |
| 情绪 | 情绪数据 | 小时级 |
| 睡眠 | 睡眠分期采样、睡眠记录 | 分钟级 |

> ⚠️ **"小时级"对"实时监护"是硬伤。** 官方提示：若穿戴设备**未连手机蓝牙**、
> 或**运动健康 App 未后台保活**，则"**无法保证数据及时性体验**"。

### 3.3 血压数据的真实来源

官方《查询健康类数据》：

> 体重、血糖、**血压**数据来自运动健康 App"设备 > 添加设备"中支持的
> **体脂秤、血糖仪、血压计**测量的数据，及**手动输入**和**应用写入**的数据集合。

即：**血压不是所有华为手表都能测**（需医用级设备如 Watch D 系列）。

### 3.4 开发者资质限制（**对高校团队影响最大**）

官方原文：

> 开放等级中，表示该数据权限为**高阶数据，暂不对个人开发者开放**。如需使用，
> 请使用**企业账号**重新注册并申请权限；基础数据，个人及企业开发者均可申请。

行业 FAQ 补充：个人开发者可申请，但只能读/写**基础**数据（如步数、热量、距离），
且需**明确项目或测试结束时间**。**审核周期约 15 个工作日。**

**结论：学生团队以个人开发者身份，只能稳定拿到基础数据；心率/血压等需企业资质。**

### 3.5 其他限制

| 限制 | 说明 |
|---|---|
| 产品类型 | 申请时**必须选"HarmonyOS 应用"** |
| 团队账号 | **暂不支持团队账号下的成员账号独立**使用 |
| 权限最小化 | 不可申请超出业务范围的权限；华为会**不定期抽查** |
| 用户授权 | 最终可用数据 = **服务审批权限 ∩ 用户逐项授权** |

## 四、智能家居（HarmonyOS Connect / 鸿蒙智联）

- 官方定位：**面向消费领域的智能硬件开放生态**，服务对象是**设备商、解决方案提供商、模组伙伴、芯片伙伴**
- 接入路径：产品解决方案 → 产品集成 → 应用开发 → 产品测试 → **产品认证**
- 健康设备接入还有独立流程：**"与华为 BD 沟通合作意向，签署合作协议后，获取 Wellness Profile 开发套件"**

**对"读取卧室灯开关时段 / 人体传感器激活 / 门锁解锁情况"的判定：**

- 这些属于**设备厂商的云侧数据**，**不存在面向第三方 App 的公开 API**
- 即使有，也需**与厂商签合作协议**——高校团队不具备该条件
- 鸿蒙智联是**统一管理平台**，不是数据开放平台

**定性：❌ 不可得**。不是"难度大"，是"没有这条路"。保留为 `EnvironmentSource` 空占位（`07` §三）。

## 六、推送能力

### 6.1 华为 Push Kit 事实

| 项 | 结论 |
|---|---|
| 支持平台 | Android、iOS、Web、Quick App、HarmonyOS |
| 权益开通 | 需在 **AppGallery Connect 开通"推送服务"** |
| 开发环境 | JDK 1.8.211+、Android Studio Chipmunk 2021.2.1+、**minSdkVersion 19+** |
| **测试建议** | 官方：**"建议使用 EMUI 10 及以上的华为手机"** |
| SDK 版本 | `com.huawei.hms:push:6.13.0.301`（2025-12-24），建议匹配 HMS Core APK 6.12.0.300+ |
| 限制 | 有 **QPS 配额**（错误码 503 = 流量控制）；错误码 6003 = 指纹证书端云不一致 |

### 6.2 ❗ 荣耀不是华为

| 依据 | 内容 |
|---|---|
| 腾讯云文档 | *"由于荣耀计划在 2024 年开始独立运营商业内容，并逐步将各项系统能力从华为转移至自身，**无法继续通过华为通道下发消息**。因此，请您尽快接入荣耀通道。"* |
| 荣耀 100 系列 | *"本系列手机为荣耀**第一款在软件层面真正意义上独立的设备，完全剔除了 HMS 与华为全家桶**"* |
| 荣耀俱乐部 | "以前的**存量机型旧版本**是可以的" → 只有老设备还能走 HMS |
| 荣耀官方 | 独立的 **HONOR Push**（developer.honor.com）；MagicOS 11 已于 2026-09-15 发布 |

**结论：荣耀新机型必须接 HONOR Push，HMS 通道对它们无效。**

### 6.3 覆盖全景

| 厂商 | 系统级通道 | 学生团队可用性 |
|---|---|---|
| 华为 | HMS Push | ✅ 个人开发者可申请 |
| 荣耀 | HONOR Push（独立） | ⚠️ 需**荣耀开发者企业账户**（腾讯云文档） |
| 小米 | 小米推送 | ⚠️ 极光文档"上架说明"：**要求必须上架应用市场** |
| OPPO / vivo / 魅族 | 各自通道 | ⚠️ 部分有上架要求 |
| 其他 Android | 无 | ❌ 只能长连接 |

**聚合方案（覆盖最广，但第三方）：**

| 服务 | 已覆盖通道 |
|---|---|
| **个推** | APNs、FCM、华为、鸿蒙、**荣耀**、小米、OPPO、vivo、魅族、个推 UPS |
| **极光** | 小米、华为、OPPO、vivo、**荣耀**、魅族、FCM、华硕、鸿蒙、蔚来 |

### 6.4 两个硬门槛

1. **企业账户**：荣耀推送需荣耀开发者**企业**账户
2. **上架要求**：小米等厂商要求**上架应用市场**才能正常推送

→ **学生团队大概率拿不到**。这决定了长连接兜底不是可选项而是必需品（`06` §二）。

### 6.5 RN 新架构时间线（与官方推送插件相关）

| 版本 | 日期 | 关键变化 |
|---|---|---|
| 0.76 | 2024-10-23 | 新架构**默认启用** |
| **0.82** | 2025-10-08 | **第一个完全在新架构上运行的版本；旧架构配置被忽略（"仅限新架构"）** |
| 0.83 | — | **移除旧架构代码** |
| **0.84** | 2026-02-11 | 继续移除旧架构组件；**Node.js 最低要求 v22** |
| **0.88** | 2026-10-12 | 当前最新稳定版（本项目锁定级别） |

> ❗ **"使用新架构"在今天不是选项，而是唯一状态。** `newArchEnabled=false` 会被忽略。

**对官方推送插件的影响：**

- `@hmscore/react-native-hms-push`（v6.13.0-302，HMS Core 团队第一方，Apache-2.0）
  是**旧式 Native Module** → 在 0.82+ 上只能走 **Interop Layer**
- 官方文档：*"The Interop Layer makes it possible to use existing native modules written for the legacy architecture with the New Architecture"* → **理论上仍可用**
- **但**：事件（推送模块的核心）正是互操作层的薄弱点；已有 RN 0.86 Bridgeless 下 `RCTEventEmitter` 失效的踩坑记录
- 该仓库有**仍 open** 的 RN 版本构建 issue（#286 / #301），第三方评估 **"Modestly maintained"**

**定性：⚠️ 大概率需要自写 TurboModule**（设计见 `06` §五）。

## 七、端到端实时语音

| 供应商 | 模型 | 结论 |
|---|---|:--:|
| **阿里云百炼** | `qwen-audio-3.1-realtime-plus` | ✅ 实时双工、支持工具调用与联网搜索、上下文 262,144；有官方 `dashscope` Python SDK + 官方示例仓库 |
| **火山引擎** | 豆包实时语音 3.0（Seeduplex） | ✅ 全双工端到端，官方文档含 Python 示例 |
| **华为云** | MaaS / SIS | ❌ **无对等产品** |

### 关键约束

1. ❗ **联网搜索与工具调用互斥**（Qwen）：`enable_search` **不能与 Function Calling 同时启用**
   → 对策：把搜索包装成自建工具走 FC（`11` §四）
2. ❗ **成本**：Qwen 音频输出 **150 元/百万 token**；且**华为云代金券不能用于阿里云/火山引擎**
3. ⭐ **`smart_turn` 语义轮次判定**（"嗯""啊"不打断）**恰好命中老人口语场景**——真实的选型理由

### 华为云路线（客观限制）

| 产品 | 能力 | 端到端实时语音 |
|---|---|:--:|
| **MaaS** | 文本/多模态 LLM，支持流式、工具调用、深度思考 | ❌ |
| **SIS** | ASR + TTS 分离（实时语音识别支持连续模式+端点检测） | ❌ |
| ModelArts | 训推平台 | ❌ |

> 华为云的路线是 **SIS(ASR) + MaaS(LLM) + SIS(TTS) 三段拼接**，问题：
> ① 延迟叠加 ② 不支持全双工打断 ③ 无法实现语义轮次判定。
> 而本项目目标用户是**口语化、带语气词、停顿长的老人**，这三条恰好是体验的决定性因素。
>
> **这是正当的客观条件限制**：换更强的团队也拿不到——因为这个产品**不存在**。

## 八、AI Agent 搜索 API

> 用途：实现自建 `web_search` 工具，绕开 Qwen `enable_search` 与 Function Calling 互斥（`11` §四）。

### 8.1 博查（BochaAI）⭐ 选定

| 项 | 结论 |
|---|---|
| 公司 | 杭州博查搜索科技有限公司 |
| 定位 | *"给 AI 用的世界知识搜索引擎"*；**DeepSeek 官方联网搜索供应方**；阿里/腾讯/字节官方推荐的搜索 API |
| 客户规模 | 60,000+ 泛企业客户 |
| 内容源 | 全网近千亿网页 + 生态内容（短视频/新闻/百科/天气/医疗/火车票/酒店/餐厅/景点/企业/学术） |
| Base URL | `https://api.bochaai.com` |
| 鉴权 | `Authorization: Bearer {{API_KEY}}` |
| **免费额度** | **控制台可免费领取 1000 次调用资源包** |
| 三个 API | Web Search、AI Search、Semantic Reranker |

**Web Search** `POST /v1/web-search`：`query`(必需) / `freshness` / `summary`(bool, 默认 false) /
`include` / `exclude`（域名白/黑名单，≤100 个）/ `count`(1–50, 默认 10)。
返回网页标题、链接、摘要与正文、发布时间、网站名称。

**AI Search** `POST /v1/ai-search`：`query` / `freshness` / `include` / `count` /
**`answer`**(bool, 默认 true) / `stream`。
返回**多模态参考源 + 总结答案 + 追问问题**，以及**结构化模态卡**
（天气卡、百科卡、**医疗卡**、日历卡、股票卡）。

**错误码**：400（参数缺失）/ 401（Key 无效或**无接口调用权限**，`ai-search` 可能需白名单）/
403（余额不足）/ 429（频率超限）/ 500。排错保留 **`log_id`**。

> ⚠️ 具体单价未核实（第三方转售渠道见"0.01 PTC/次"，非官方口径）→ `12` T-48。

**官方周边**（可参考，不引入项目）：`Bocha-Labs/bocha-skills`（Apache-2.0，含 `bocha-web-search` SKILL.md）、
`Bocha-Labs/bocha-search-mcp`（MIT，Python MCP Server）。

### 8.2 Tavily（备选）

| 项 | 结论 |
|---|---|
| 定位 | 专为 AI Agent 打造的实时网络搜索 API |
| Python SDK | `tavily-python`（MIT，1.4k★），有同步/异步客户端 |
| 特点 | 返回经结构化提取与 chunk 分段的结果，可直接注入 RAG；有 LangChain 集成 |
| ⚠️ 风险 | **海外服务**，大陆访问的稳定性与合规性需评估 |

### 8.3 定性

> ✅ **可行**。博查是国内公司、专为 LLM 设计、有免费额度、覆盖天气/医疗等结构化模态卡，
> 与本项目"老人常问天气与生活小问题"的场景高度匹配。
> Tavily 作为技术备选，但因是海外服务，**不作为主选**。

## 九、华为云产品事实

| 产品 | 用途 | 关键约束 |
|---|---|---|
| **CodeArts 代码智能体（码道）** | AI 编码、项目级代码生成、单元测试、Skills 技能包、可接入 DeepSeek/GLM/本地模型 | 赛题一 M1 强制；有**沙箱模式会拦截 KooCLI**（`09` §五） |
| **MaaS 模型即服务** | 预置模型免部署调用；支持工具调用、深度思考开关、上下文缓存 | **仅"西南-贵阳一"**；开通自动含所有版本；**不支持关闭**；三方服务仅个人用户可开通。详见 `11` §五 |
| **RDS / Redis** | 结构化数据 / 会话缓存限流 | 赛题一 M3 强制 |
| **ECS / VPC / EIP** | 应用部署与网络 | 赛题一 M4 要求公网可访问 |
| **SIS** | ASR / TTS | 分段式，作语音降级路径 |
| **SMN** | 云资源运维通知 | **不是 App 推送服务** |

**KooCLI**（华为云命令行工具服务，原名 HCloud CLI）：为 API Explorer 上的云服务 API 提供的命令行管理工具。
支持 Windows / Linux / macOS / Docker（**无移动端**）；本体自带运行时，不需预装 Java/Python。详见部署 skill。
