# 03 · 产品与 MVP

---

## 一、两个客户端

### 1.1 老人端

| 项 | 内容 |
|---|---|
| 首页入口 | **只保留 3 个**：① 联系家人 ② 我有件事想说 ③ 查看事情进度 |
| 交互原则 | 大字、大按钮、少步骤、**确认后才分享** |
| 输入方式 | 语音为主（全双工，`04` §一）；文字输入为备选 |
| Agent 角色 | 生成**草稿**；老人可**修改 / 确认 / 取消**；**不能默认替老人发送** |
| 事项展示 | 清晰状态：等待接手 / 处理中 / 已完成 / 待跟进 |
| 桌面小组件 | 「我有件事想说」大按钮 + 今日事项状态（Kotlin 实现，`06` §4.4） |

### 1.2 亲属端

| 项 | 内容 |
|---|---|
| 展示范围 | **仅展示老人主动授权分享的事项**；不默认开放聊天或个人信息 |
| 核心操作 | 接手 → 更新进度 → 填写处理结果 |
| 同步 | 老人端同步展示状态 |
| 增强项 | 家庭联系计划：约定联系时间、提醒双方、未确认时提示重新安排 |

## 二、端到端闭环

```
表达 → 确认 → 接手 → 处理 → 反馈 → 老人知晓
```

| # | 角色 | 动作 |
|:--:|---|---|
| 1 | 老人 | 语音或文字输入自然语言需求 |
| 2 | 语音层 | 听清、判断轮次结束、**立即出声安抚** + 异步转事务层（`04` §二的先应答后落实） |
| 3 | 事务层 | 提取事项内容 / 时间 / 对象；**不确定时返回澄清请求** |
| 4 | 系统 | 生成事项草稿，显示内容与计划分享的亲属 |
| 5 | 老人 | 检查内容、接收人、分享范围后，**确认发送或取消** |
| 6 | 亲属 | 收到授权事项，选择"我来处理" |
| 7 | 亲属 | 更新为"处理中"，完成后填写结果并标记"已完成" |
| 8 | 老人端 | 同步显示状态 |

## 三、事项状态机

```
草稿(draft) ──老人确认──→ 待接手(pending)
   │                          │
   └──老人取消──→ 已取消       ├──亲属接手──→ 处理中(in_progress)
   (cancelled)                │                    │
                              │                    ├──反馈完成──→ 已完成(done)
                              │                    └──超时未响应──→ 待跟进(overdue)
                              └──亲属拒绝/超时──→ 待重新分配(reassign)
```

## 四、角色—权限矩阵

> 竞争力 C4「授权与可追踪性」的落地定义，也是答辩最易被追问的点。

| 资源 / 操作 | 老人 | 已绑定亲属 | 未授权亲属 | 后台 | Agent |
|---|:--:|:--:|:--:|:--:|:--:|
| 创建事项草稿 | ✅ | ❌ | ❌ | — | ✅（代理，需老人确认） |
| **确认发送**事项 | ✅ | ❌ | ❌ | ❌ | ❌ **（Agent 无此权限）** |
| 取消 / 撤回事项 | ✅ | ❌ | ❌ | — | ❌ |
| 查看本人创建的事项 | ✅ | — | — | — | ✅（限当前会话） |
| 查看被授权的事项 | — | ✅ | ❌ | — | ✅（限当前会话） |
| 接手 / 更新进度 | ❌ | ✅ | ❌ | — | ❌ |
| 查看老人全部聊天记录 | ✅ | ❌ **默认不开放** | ❌ | 仅审计 | ❌ |
| 增删绑定关系 | ✅ | ❌ | ❌ | 校验 | ❌ |
| 撤销授权 | ✅ | ❌ | ❌ | 执行 | ❌ |
| 修改分享范围 | ✅ | ❌ | ❌ | 执行 | ❌（须重新确认） |

**三条不可逾越的规则：**

1. **Agent 永远不能替老人做授权决定**——只能生成草稿并请求确认
2. **权限校验发生在后台，不发生在 Agent**——Agent 的输出不可信
3. **扩大共享范围必须重新授权**——新增接收人、改变重要安排都算（`04` §十）

## 五、数据模型

```
User
  id, role(elder|relative), name, phone, huawei_account?, created_at

Binding                       # 老人—亲属绑定关系
  id, elder_id, relative_id, status(pending|active|revoked),
  granted_scopes[], created_at, revoked_at

Item                          # 事项（核心实体）
  id, elder_id, created_by(agent|elder),
  action_type, content, expected_time, deadline,
  status(draft|pending|in_progress|done|overdue|reassign|cancelled),
  confirmed_at,               # 老人确认时刻 —— 审计关键字段
  created_at, updated_at

ItemGrant                     # 事项级授权（谁可以看/接手）
  id, item_id, relative_id, scope(view|handle), granted_at, revoked_at

ItemEvent                     # 状态变更与操作记录（可追踪性 + 审计）
  id, item_id, actor_id, actor_type(elder|relative|agent|system),
  event_type(create|confirm|cancel|take|update_progress|complete|remind|reassign),
  payload, occurred_at

MemoryRecord                  # 长期记忆（04 §六）
  id, elder_id, kind(fact|preference|contact|routine),
  content, source, confidence, version, valid_from, valid_to
```

**设计要点：**

- `ItemGrant` 与 `Binding` 分离 → 支持"授权了某个亲属，但只对某件事开放"
- `ItemEvent` 只追加不修改 → 可追踪性
- `MemoryRecord` 带 `version` / `valid_from` / `valid_to` → 支持审计与防膨胀
- `confirmed_at` 是审计与合规的关键字段

## 六、MVP 边界

### 6.1 必须完成

| 模块 | 必须项 | 验收标准 |
|---|---|---|
| 老人端 | 语音输入需求、查看 AI 草稿、确认/取消、查看状态 | 老人可独立完成"提出需求 → 确认分享 → 查看进度" |
| 亲属端 | 接收授权事项、接手、更新状态、反馈结果 | 亲属可完成"接手 → 处理中 → 已完成" |
| 后台 | 双端账号关联、事项存储与同步、**权限校验** | 未授权亲属无法访问；撤销权限后立即失效 |
| 语音层 | 全双工对话 + 至少一个 `request_task` 工作流 | 可展示工具调用日志 |
| 测试 | 成功路径 + 取消 / 信息不完整 / 工具失败 | 至少 4 条路径可演示 |

### 6.2 第二阶段

- 系统通知、日历接口集成（**先核实接口与授权**）
- 家庭联系计划自动提醒
- ESP32 等实体语音终端

### 6.3 一期不做

见 `01` §三 的 A/B 类清单。要点：不投硬件、不接智能家居、不做实时健康监护、不做医疗端、不读微信。

## 七、团队分工

| 角色 | 任务 | 产出 |
|---|---|---|
| **A · 前端与体验** | 双端界面、交互流程、**可访问性**（大字、对比度、语音） | 双端可操作应用 |
| **B · Agent 与后端** | 结构化输出、工具调用、API、数据模型、**权限校验**、云上部署 | Agent 工作流 + 后台接口 |
| **C · 产品、测试与集成** | 用户访谈、测试用例、部署、**演示脚本与文档**、答辩材料 | 测试记录、演示环境、答辩材料 |
| **D · 指导教师** | 方向把关、资源协调、合规与伦理审查 | 报名资格要件 |

**三条纪律：**
1. 三个人都要理解完整业务流程——避免只有一人能现场演示
2. 三个人都要能跑通系统——ICT 赛规定"代码无法复现 PPT 效果将取消资格"（`00` R5）
3. 指导教师第一天就介入——报名后不得更换（`00` R3）
