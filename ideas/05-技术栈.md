## 一、逻辑架构

```text
老人语音盒 ── HTTPS 音频 ───────────→ 语音接口／会话
     │                                    │
     └─ MQTTS → IoTDA → 设备接入适配层 ────┤
药盒节点 ─ MQTTS → IoTDA ──────────────────┤
                                          ▼
亲属 Web／移动接收端 ─ HTTPS ─→ 身份、绑定、资源授权
                                    │
                      ┌─────────────┴──────────────┐
                      │ 完整确定性业务服务         │
                      │ 事项／药品计划／别名／记忆 │
                      │ 事件关联／调度／通知／审计 │
                      └────┬───────────┬──────────┘
                           ▼           ▼
                    RDS 业务事实   Redis 辅助能力
                    ＋持久化任务   会话／频控／缓存
                           │
                     后台发送／有限重试
                     ├ 主通知＋补充 Webhook
                     └ IoTDA 下行 → 盒子执行及回执

Agent／模型：只提供待校验的理解、澄清、候选和摘要，不绕过业务写入口。
```

音频不默认塞入 IoTDA 消息分片。具体设备 SDK、音频通道、规则转发、认证和接口字段在 T-54～T-59 验证；图不是已部署状态。

## 二、技术职责与选型状态

| 层 | 当前方向 | 状态／边界 |
|---|---|---|
| 老人交互 | 无触摸屏语音盒；按键录音、确认、取消 | 已决策；尺寸、按键方式与音频链路需样机验证 |
| 传感 | 药盒开合节点，IoTDA 上报 | 已决策；板型、传感器、参数未锁定，不测吞服 |
| 固件 | 依据节点能力选择；适合时优先 OpenHarmony | 不强求同一系统；ESP-IDF 不冒充 OpenHarmony；SDK 语言见 `08` §十二 |
| 家庭界面 | Web 亲属／配置入口＋移动通知接收能力 | 当前设计方向；最终客户端路线、框架、封装和主推送见 T-67，不视为已全部选定 |
| 后端 | 沿用 Python 方案，保留完整业务能力 | 框架、RDS 引擎和最终 schema 需验证；IoTDA 应用侧 Python SDK 已有文档依据 |
| 数据 | RDS 持久化；Redis 会话／缓存／频控等辅助 | 关键事实和唯一发送任务不得仅存 Redis |
| 语音 | 首个硬件里程碑为录音上传、识别与播放 | 服务和音频格式需实测；旧 Qwen／全双工方案见 `11`，不再是开工硬前置 |
| 事务模型 | 华为云 MaaS 为既有候选方向 | 具体模型、权限、计费及工具准确性仍需实测，非因“全栈覆盖”强制堆产品 |
| 搜索 | 既有博查方案保留为辅助候选 | 不用于现场生成个体化用药指导，不阻塞首个硬件闭环 |
| 推送 | 既有 JPush／HMS 候选实测选择；站内待办持久化 | Webhook 只补充；长连接只解决在线同步，不冒充离线必达 |
| 检索 | 先结构化记录与全文检索 | FTS／BM25 取决于实际引擎；不把向量检索等同于 RAG |
| 部署 | CodeArts＋已有智能体／Skills，KooCLI 为执行候选 | 先验证既有能力，再补项目拓扑；不把示意脚本算作完整部署 |

旧 RN 版本、TurboModule、自建长连接、双模型和固定区域的细化设计保留供比较，不再作为所有节点必须执行的统一实施指令。涉及这些路线时重新确认相应版本和能力，不凭旧文档推定可用。

## 三、华为技术的真实职责与证据

| 技术 | 职责 | 应保存的证据 |
|---|---|---|
| CodeArts | 需求理解、编码、构建、修复、上线 | 实际会话／录屏／提交；不只留安装截图 |
| 已有智能体与 Skills | 资源开通创建、关联和部署；按需补项目特有技能 | 导入／调用记录和可复现执行；自定义两个 Skill 不是官网独立硬指标 |
| RDS／Redis | 业务持久化及辅助能力 | 实际开通关联、连接、读写与恢复；查询实例不单独证明创建流程 |
| ECS／网络等部署资源 | 云上应用与在线 Demo | 在线访问、健康检查、配置注入和失败恢复 |
| IoTDA | 设备身份、数据上报、下行与设备状态 | 两类节点实测、重发／重连／过期处理 |
| MaaS | 适用时承担理解和澄清 | 调用日志与准确性、延迟和费用实测 |
| OpenHarmony | 适用时承担真实固件功能 | 对应板型、版本、源码、构建与真机运行证据 |

赛事技术要求及评分见 `00`。没有“采用更多产品保证晋级”的已核实规则；不为覆盖度额外引入训练、昇腾部署或其他无实际职责组件。

## 四、开发与开源纪律

- 人与设备身份、绑定、资源级授权、幂等、审计与失败恢复不可省略。
- 设备仅有独立的设备作用域凭据；云 AK/SK、模型 Key 不进设备、客户端、仓库或公开日志。
- 固件、音频、TLS／MQTT 库需锁定兼容组合，不默认新版 SDK 与旧例程兼容。
- 开源包含源码、构建／接线、依赖、配置模板、部署清理说明和合成测试集；不包含真实处方、聊天或密钥。
- 原部署文档引用的 `.agents/skills/huaweicloud-koocli-deploy/` 当前检出未找到，不能列为已交付；见 T-72。
- 里程碑和预算按 `12` 复核；2026-12-01 是团队内部上云目标，不冒充官网明确截止。
