# 02 · 用户与场景

---

## 一、目标用户

### 1.1 锁定的人群

> **会使用智能手机、认知能力基本正常，但在复杂操作上容易受挫、容易漏跟进的独居 / 空巢老人。**

**为什么排除两端：**

| 人群 | 排除理由 |
|---|---|
| 完全不会用智能手机的老人 | 需实体设备或无屏交互，成本超出 3 人团队（B 类取舍） |
| **有轻度认知困难的老人** | 涉医疗辅助定位、伦理审查、监护人授权模型，风险与合规成本不适合 3 人规模（B 类取舍，远期） |
| ✅ **"会用但用得吃力"的老人** | 有明确痛点、有智能手机、能配合测试——**可触及且有价值** |

### 1.2 老人画像

| 维度 | 描述 |
|---|---|
| 年龄 | 65–80 岁为主 |
| 居住 | 独居 / 空巢（子女在异地） |
| 健康 | 有 1–2 种慢性病，生活自理 |
| 数字素养 | 会用微信收发消息、会视频通话；不会用复杂 App、不会填长表单 |
| 沟通偏好 | 倾向语音；文字输入慢；"要点很多次"没耐心 |
| 情感特征 | 怕打扰子女；需求表达含糊、绕弯子 |
| 设备 | 智能手机，**不预设是华为** |

### 1.3 亲属画像

| 维度 | 描述 |
|---|---|
| 年龄 | 30–55 岁 |
| 特征 | 工作忙、异地、对父母有愧疚感 |
| 痛点 | 收到消息时在忙，回头忘了；不知道父母到底有没有被照顾好 |
| 关注 | **不想被大量无关信息淹没**，只想看到"需要我做的事" |
| 顾虑 | 隐私（不想让所有亲戚都看到）；被指责"不孝顺" |

### 1.4 医疗人员（远期，不做）

原始概念含医疗人员角色，**降级为远期**：

1. 其核心需求（病史、用药、客观检查数据）的获取路径已核实为受限或不可得（`08` §三）
2. 引入医疗角色触发**医疗数据合规**问题（敏感个人信息）
3. 三方协作复杂度翻倍，3 人团队 8 个月无法验证三方价值
4. v2 的四个组成部分里本就没有医疗端

## 二、平台假设

**产品主体不绑定华为硬件。** 目标用户中相当比例用小米 / OPPO / vivo / 荣耀。

| 层 | 策略 |
|---|---|
| 平台层 | Android 优先（因离线推送，`06` §一），但**不绑定华为硬件**——用 `PushChannel` / `VitalSource` / `RealtimeVoiceProvider` 抽象隔离 |
| 华为技术 | 作为**赛题要求的技术栈**（华为云）与**可选增强**（Push Kit、Health Kit），并在方案中标注"该能力仅对华为设备用户可用" |

## 三、核心场景

### S1 · 模糊需求 → 澄清 → 成为事项（主场景，答辩必演）

```
老人："家里米快没了，谁有空周末帮我带一袋？"
  ↓ 提取：动作=购买大米，时间=周末，对象=未指定
  ↓ 对象缺失 → 追问
Agent："您是想请哪位家人帮忙？"
老人："问问我儿子吧。"
  ↓ 生成草稿（内容 + 接收人 + 分享范围）
Agent："我准备把这件事告诉小陈：『家里米快没了，周末方便带一袋吗？』可以发送吗？"
老人："可以。"
  ↓ 确认 → 创建事项 → 亲属接手 → 处理中 → 完成反馈 → 老人端状态同步
```

### S2 · 潜在需求推断（多假设推理）

```
老人："最近家里挺冷清的。"
Agent："最近是不是比较想和家里人聊聊天？"          ← 假设，用提问而非断言
老人："是啊，女儿工作忙，我也不好总打扰她。"
Agent："我可以帮您问问她，这周有没有方便通话的时间。您愿意吗？"
```

**规范**：可识别情绪线索，但**不得直接推断老人心理状态**；证据不足时用提问澄清。

### S3 · 约定时间已过但无反馈

```
D1  老人同意创建关怀事项
D2  女儿收到通知，选择"周六下午联系妈妈" → 记录安排
D3  约定时间已过、无反馈 → 在频率限制内询问女儿是否已完成
D4  老人："昨天和女儿聊了很久，挺开心的"
    → 识别可能是对之前事项的反馈 → 必要确认后关联历史事项
```

### S4 · 任务条件变化 → 重新分配

```
亲属 A 无法处理 → 结合历史协作关系 + 当前反馈 + 任务要求生成替代方案
                → 多轮协商 → **回到老人处重新确认**（不可跳过）
```

### S5 · 失败与异常路径（答辩必须演示）

| 场景 | 期望行为 |
|---|---|
| 网络错误 | 明确提示，草稿不丢失，可重试 |
| 工具调用失败 | 告知"没能创建成功"，不静默失败 |
| 重复提交 | 幂等处理，不产生重复事项 |
| 亲属长时间未响应 | 状态转"待跟进"，按频率限制提醒，不轰炸 |
| 老人中途反悔 | 随时可取消草稿或撤销已分享事项 |
| 语音识别错误 | 可修改草稿文本后确认 |
| 澄清轮次过多 | **设上限**（3 轮），允许随时中断 |
| 老人表达自伤倾向 | 触发安全兜底（提示联系家人/热线），**不做心理评估** |

## 四、用户验证计划

| 阶段 | 时间 | 对象 | 方法 | 产出 |
|---|---|---|---|---|
| R1 需求访谈 | 2026-11 | 5–10 位老人 + 5 位家属 | 半结构化访谈 | 痛点清单、现有工具使用、信息共享顾虑 |
| R2 概念测试 | 2026-12 | 5 位老人 | 线框图走查 | 首页入口可理解性、确认流程可接受性 |
| R3 可用性测试 | 2027-01 | 8–10 位老人 + 家属 | 真实任务全流程 | 任务完成率、操作时间、卡点（`10` E-01/E-02） |
| R4 闭环验证 | 2027-02 | 3–5 个家庭 × 2 周 | 真实使用 | 事项闭环率、主动性（E-03/E-12） |

### 4.1 访谈提纲（R1，20–30 分钟/人）

**对老人：**
1. 您平时怎么跟子女联系？多久一次？
2. 有没有过"想让子女帮忙做件事，但最后没说"或"说了但没下文"的情况？能举例吗？
3. 那种时候您会怎么处理？会觉得不好意思催吗？
4. 手机里装了哪些 App？哪个用得最熟？
5. 如果有个 App 能帮您把想说的整理成一条"事情"发给孩子，您觉得有用吗？会有什么顾虑？
6. 您愿意让孩子看到您说的哪些内容？哪些不想让他们看到？

**对家属：**
1. 父母上次请您帮忙做一件具体的事，是什么时候？后来怎么样了？
2. 有没有过"当时忙，回头忘了"？后来怎么处理的？
3. 您希望知道父母的哪些情况？不希望被哪些信息打扰？
4. 如果收到"父母需要您做 X"的通知，您希望它长什么样？
5. 会担心隐私吗？比如其他亲戚也能看到？
6. 您觉得这类工具最可能在哪一步失败？

### 4.2 伦理事项

- 知情同意（口头 + 记录）
- 不采集不必要的个人健康信息
- 老人可随时退出
- **不得在未获授权时录音录像**
- 确认学校是否要求**伦理审查**（`12` T-06）
