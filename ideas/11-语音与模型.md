# 11 · 全双工语音、并行处理与模型候选

> 全双工与并行 Agent 是核心交付目标，不再是硬件完成后的增强项。当前没有本项目实测通过证据；供应商文档支持、优先 PoC 与最终定型分开陈述。

## 一、用户需要什么体验

老人可以连续交流、停顿、附和、插话、改口和结束。后台整理重要信息时，对话不必被同步办事流程锁住；重要结果能在适当时机准确返回。

全双工不等于全天监听、远场唤醒或绝对零等待。长语音交流也不应被自动压成任务；聊天本身与后续记忆都需要保留价值。

## 二、核心验收而非术语验收

| 维度 | 需真实测量 |
|---|---|
| 双向音频 | 手机录放音并发、回声、耳机／外放、设备切换 |
| 打断 | 用户说话后旧播放停止，取消结果与实际播放一致 |
| 轮次 | 长停顿、附和、重复、自我纠正不误截断；不假设某 VAD 自动解决 |
| 长表达 | 约 60 秒及更长脚本中的重要信息覆盖、转写修订、上下文截断 |
| 并行 | 对话继续时 Agent 仍能整理、存储和处理任务，有事件时间线证据 |
| 延迟 | 说话响应、打断生效、后台落实、澄清反馈分别计时 |
| 恢复 | 弱网、断流、模型超时、会话结束、工作进程重启 |
| 业务反馈 | 听到了／处理中／保存成功／发送未知不混淆 |

样本长度为测试设计，不是普遍用户统计。平均值、分位数、失败与人工干预分别报告，数值阈值在 PoC 和样本确定后制定。

## 三、优先 PoC：Qwen-Audio 实时语音

本轮重新读取 [官方指南](https://help.aliyun.com/zh/model-studio/qwen-audio-realtime-user-guides)，记录见 [08](08-外部依赖核查.md)。

- 指南以 `qwen-audio-3.1-realtime-plus` 展示原生 WebSocket Python 示例，另介绍 AOQ／WebRTC。
- `smart_turn` 与 Function Calling 有文档依据，但老人口语、工具可靠性与本项目手机链路尚未实测。
- 内置搜索与 FC 的互斥只按所查路径理解；公共搜索可以另选适配，不为它阻塞核心。
- 所查音频历史存在轮次和累计音频保留上限，较早历史会被丢弃。模型的会话上下文不能替代自建长期记忆。
- Python 原生示例不等于已验证 `dashscope` 实时接口或 AOQ 手机 SDK。若采用这些 SDK，另核语言、平台和版本。
- 价格、地域、工作空间、密钥机制、临时凭证与数据政策在使用前核实，不沿用旧固定单价当预算结果。

首个 PoC 可验证手机—后端—语音服务的实际往返，再接入持久化轮次与后台 Agent。只有端到端打断和并行通过才标核心完成。

## 四、Agent 推理：MaaS 候选

本轮重新读取 [标准 API V2](https://support.huaweicloud.com/model-call-maas/model-call-019.html)：HTTP API、Python `requests` 示例、流式与工具调用有依据，具体模型能力不同。

openPangu 等可以做候选；不能仅因是华为产品、支持 `auto` 或可以关闭思考就断言适合全部工具。工具参数校验、权限与确认由业务服务负责。

比较标准是：重要信息覆盖、记忆来源保真、任务与共享正确性、延迟、费用和失败恢复。缓存是需测量的成本因素，不保证延迟和命中率；不默认代金券可抵扣。

若语音与 Agent 分别使用模型，统一输出协调；单模型也须满足核心职责和可靠边界，不为“双模型”标签强行增加依赖。

## 五、并行通路的选择

| 通路 | 优点 | 必须处理的风险 |
|---|---|---|
| 语音模型工具调用触发 Agent | 明确动作可快速衔接 | 纯闲聊中有价值记忆可能不触发，工具漏判 |
| 完整轮次／转写事件驱动 Agent | 可以覆盖无指令的背景、近况与习惯 | 临时转写、更正、重复处理与时效 |
| 两者组合 | 同时支持快速动作与背景整理 | 双路事件去重、同一意愿唯一业务结果 |

具体契约在 T-77 定案，见 [04](04-Agent架构.md)。不能只把 Agent 暴露为一个工具，就声称后台已持续整理所有闲聊。

输出协调决定何时说结果，不能让两个模型同时发声。回应可以先发生，但存储未完成不能说已保存，后台延迟也不能被文字上抹去。

## 六、替代与降级

- 豆包原全双工文档本轮未成功读取，仅保留候选线索，重新核查协议、Python 路径与权限后再比较。
- 分项 ASR＋LLM＋TTS 不是现成全双工证明；但自建系统是否支持打断取决于实现，不能断言永远不可能。
- 所查 MaaS／SIS 文档不等于某厂商全部产品，不用“这个产品不存在”作为架构理由。
- 分段录音、文字和 Mock 可开发、回归、故障降级，明确 `fullDuplex=false`；不抵扣核心验收。
- 供应商切换仍需重验音频、转写语义、工具、权限、成本与数据流向，不能承诺只换配置。

## 七、语音与生活场景的安全

语音识别错误可能改错药名、时间或共享对象，不只是体验问题。高影响动作需明确复述与当前上下文确认，不能让语音模型直接写库。

用药内容播报来自有来源的有效安排，AI 不自行生成剂量、补服或改药。搜索结果不直接当医嘱，固定字数截断不能丢失条件、单位和否定。

对情绪线索可以回应和邀请表达，不断言心理状态，不把普通闲聊转风险评分。不得合成父母声音冒充原话，也不自动用子女身份发送问候。

## 八、成本、隐私与可观测性

- 长期 API Key 仅在受控服务端，手机临时凭证只在供应商实际支持且完成限权后采用。
- 按需开启会话，空闲释放连接，不默认持续后台收音。
- 长语音不能为节约费用被默默丢弃；使用限制或降级向用户明确说明。
- 记录事件关联、处理状态、耗时与必要用量，不全量公开音频、转写、推理过程或私密查询。
- 原始音频、转写、私人记忆、家庭原话的保留和共享分别设计。
- 语音层自然度与后台成功率分别报告，不用一个首 Token 延迟代表全链路。
