## 二、华为云没有对等的端到端实时语音（客观限制）

| 华为云产品 | 能力 | 端到端实时语音 |
|---|---|:--:|
| **MaaS** | 文本/多模态 LLM，支持流式、工具调用、深度思考开关、上下文缓存 | ❌ |
| **SIS** | ASR + TTS **分离**（实时语音识别支持连续模式 + 端点检测） | ❌ |
| ModelArts | 训推平台 | ❌ |

华为云的路线是 **SIS(ASR) + MaaS(LLM) + SIS(TTS) 三段拼接**，三个问题：

1. **延迟叠加**（ASR → LLM → TTS，链路长）
2. **不支持真正的全双工**（无法在模型说话时被打断）
3. **不支持语义轮次判定**（`smart_turn` 这类能力无从实现）

而本项目目标用户是**口语化、带语气词、停顿长的老人**，全双工与语义轮次判定**恰好是体验的决定性因素**。

> **这是正当的客观条件限制**：换更强的团队也拿不到——因为这个产品**不存在**。
> → 实时语音通道采用第三方；**华为云承担平台与事务层职责**（§五 双模型分工）。
> → 在材料中按 `07` §7.1 的分层写法如实陈述，并给出替代路径。

## 三、语音模型选型

### 3.1 Qwen `qwen-audio-3.1-realtime-plus`

| 项 | 内容 |
|---|---|
| 定位 | **实时双工语音对话模型**，支持文本和音频输入输出、**工具调用**、**联网搜索**、声音复刻 |
| 默认音色 | `longanqian_v3.1` |
| 上下文 | 262,144 tokens；最大输入 245,760；最大输出 16,384 |
| 接入协议 | **WebSocket**、**AOQ**、**WebRTC** |
| 地域 | 华北2（北京）、新加坡 |

**价格（华北2 北京，每百万 Token）：**

| 文本输入 | 音频输入 | 文本输出 | **音频输出** |
|---:|---:|---:|---:|
| 5 元 | 40 元 | 40 元 | **150 元** |

> ⚠️ **音频输出 150 元/百万 token 是本项目最大的单项成本风险。** 对策见 §七。

**三种交互模式（对老人场景价值极高）：**

| 模式 | 说明 | 意义 |
|---|---|---|
| `server_vad` | 声学 VAD，服务端自动判断起止 | 基础可用 |
| **`smart_turn`** | **"融合声学感知与语义理解判断轮次边界，无意义附和声（如"嗯""啊"）不会打断对话"** | ⭐⭐⭐ **老人场景的关键能力** |
| `push-to-talk` | 手动控制 | 老人端"按住说话"备选 |

> ⭐ **`smart_turn` 直接解决一个真实痛点**：老人说话常带语气词、停顿长、自我重复。
> 传统 VAD 会被"嗯""啊"打断，体验很差。
> **这一条应写进申报书的技术方案**——它证明我们不是随便选了个模型，而是**按场景特征选的**。

**Python SDK：**

| 项 | 内容 |
|---|---|
| 官方 SDK | **`dashscope`**（PyPI） |
| 版本要求 | 实时多模态 ≥ 1.26.5；实时语音合成 ≥ 1.25.11 |
| 官方示例仓库 | [`aliyun/alibabacloud-bailian-speech-demo`](https://github.com/aliyun/alibabacloud-bailian-speech-demo) |
| SDK 结构 | `fun_realtime/` 负责 WebSocket 连接、事件序列化、会话配置、音频编解码；**有意保持精简**（无轮次状态机、无内置路由器） |

> ✅ **`fun_realtime` "有意保持精简"很适合我们**——不预设架构，正好套进 `04` 的 ReAct 循环
> 和 `07` 的端口设计，不会打架。

### 3.2 豆包（Seeduplex 3.0）

| 项 | 内容 |
|---|---|
| 模型 | 豆包实时语音模型 3.0（Seeduplex），全双工端到端 |
| 新协议地址 | `wss://openspeech.bytedance.com/api/v3/duplex/realtime/dialogue` |
| 旧协议地址 | `wss://openspeech.bytedance.com/api/v3/realtime/dialogue` |
| 协议 | 标准化 Realtime 事件语义（`session.create` / `input_audio_buffer.append` / `response.cancel` …），WebSocket 纯 JSON 文本帧 |

| 工具调用 | session 内含 **`tools`** 字段 |
| 官方示例 | Go 示例 + **Python 示例**；另有 Web Demo |
| ⚠️ 注意 | "3.0 采用全新的 Realtime 事件协议，**与原版本差异较大**" |

> 与旧协议 `/v3/realtime/dialogue` 不同。**网上教程多数是旧协议，照抄会踩坑。**

**社区 Python 参考**：[`SUAT-AIRI/RealtimeDialog-doubao`](https://github.com/SUAT-AIRI/RealtimeDialog-doubao)（MIT）。
⚠️ 社区项目非官方支持，评估时不要当依赖。

### 3.3 对比与结论

| 维度 | Qwen `-realtime-plus` | 豆包 Seeduplex 3.0 |
|---|---|---|
| 中文文档完整度 | ⭐⭐⭐ 最全，中文一手文档 | ⭐⭐ 较全 |
| 官方 Python SDK | ✅ `dashscope` + 官方示例仓库 | ⚠️ 官方只有示例代码，SDK 需自行封装 |
| 轮次判定 | ⭐⭐⭐ **`smart_turn`（语气词不打断）** | ⭐⭐ 需核实 |
| 工具调用 | ✅ Function Calling | ✅ `session.tools` |
| 联网搜索 | ⚠️ `enable_search`，**与 FC 互斥** | ✅ extension 透传（是否与 tools 互斥待核实） |
| 价格 | 已核实 | ⚠️ 待核实 |

> ✅ **选定 Qwen**。理由不是"更好"，而是：
> ① 中文一手文档最全（赶工期时最重要）② `smart_turn` 恰好命中老人场景
> ③ 有官方 Python SDK 与示例，少踩坑。**但保留可替换性**（§八）。

## 四、联网搜索的设计（绕开 `enable_search` 互斥）

### 4.1 问题

```
需要：Function Calling（创建事项、查状态、写记忆）
也需要：联网搜索（天气、生活小问题）
Qwen 的约束：enable_search 与 Function Calling 不能同时启用
```

### 4.2 ❌ 不采用的方案

| 方案 | 为什么不行 |
|---|---|
| 开 `enable_search`，放弃 FC | 事务层废了，退化成聊天机器人 |
| 按"模式"切换（闲聊开搜索 / 事务开 FC） | 一句话可能同时含闲聊和事务；模式判定本身又要 FC |
| 换豆包用 extension 搜索 | 同样面临"是否与 tools 互斥"的未知；换供应商等于重新踩坑 |

### 4.3 ✅ 采用：把搜索包装成自建工具

```
Function Calling 工具集新增：
  web_search(query: string) → {answer, sources[]}
      │
      └── 后端（Python）调第三方搜索 API
          然后用 FC 的 observe 结果喂回模型生成话术
```

| 收益 | 说明 |
|---|---|
| **不冲突** | 全程只用 Function Calling，不碰 `enable_search` |
| **可控** | 搜什么、什么时候搜、结果怎么用，都在我们手里 |
| **可引用** | 能强制模型返回来源（与 `04` §十一 的证据等级思路一致） |
| **可审计** | 搜索行为进 `ItemEvent` 审计表 |
| **可替换** | 搜索供应商可换（博查 / Tavily / 夸克 / 自建） |
| **答辩友好** | 是"Agent 工具设计"的正面例子，不是"调了个开关" |

> 顺带解决一个隐患：`enable_search` 是模型自主决定要不要搜，
> 而**老人场景更希望"搜不搜"是可控的**（避免答非所问、避免把无关信息说给老人听）。

## 五、华为云 MaaS

### 5.1 是什么

> **MaaS（Model as a Service，模型即服务）** 是华为云的一站式大模型调用与托管服务。
> 把主流大模型预置好、免部署、按 Token 计费地开放出来，
> **不需要自己买卡、部署、运维**，一个 HTTP 请求就能调用。

**官方定义**：

> "MaaS 是一种基于 AI 算力适配主流大模型的服务模式。它作为企业与开发者的大模型敏捷应用枢纽，
> **免除了用户自行进行模型训练、部署与运维的高昂成本**。"

**与已有技术的关系（容易搞混）：**

```
CodeArts 代码智能体   ← 【开发工具】赛题一强制
       │  官方明确"兼容主流 AI 工具……支持华为云码道（CodeArts）"
       └─→ MaaS 可作 CodeArts 的模型后端
MaaS 模型即服务       ← 【推理引擎】我们要用的
ModelArts             ← 【底层平台】MaaS 是它的一个能力面，需配委托授权
SIS 语音交互服务       ← 【ASR/TTS】分段式
```

**四个选它的理由：**
1. **赛题一的"华为云"技术栈体现**
2. **支持工具调用**（OpenAI 兼容的 `tools` / `tool_choice`）—— Agent 的命脉
3. **有上下文缓存折扣**，官方明说"特别适用于**多轮对话、工具调用**" → **精确命中我们的场景**
4. **是华为云自家产品，代金券理论上可覆盖**（而 Qwen/豆包必须自付）

### 5.3 选型建议（两条硬约束驱动）

**约束一：`tool_choice` 支持度不同** — openPangu 只有 `none`/`auto`；需要**强制调用某工具**时须用 DeepSeek / GLM。
AgeGuard 以 `auto` 为主，openPangu 够用。

**约束二：`thinking.type` 能否关闭** — **GLM-5.3 强制开思考**，
会显著拉长首 Token 时间 → **不适合实时对话**。

| 用途 | 模型 | 理由 |
|---|---|---|
| **实时对话 / 事项理解** | `openpangu-2.0-flash` + `thinking=disabled` | 低延迟；auto 工具调用够用 |
| 复杂推理 / 多假设推断 | `openpangu-2.0-pro` 或 `deepseek-v4.1-flash` | 需要更强推理 |
| 记忆闲时整理 | `deepseek-v4-flash` | 离线任务，成本敏感 |

> ⭐ **用 openPangu 作主模型，是"赛题契合度"与"技术可用性"的最佳交点**：
> 华为自家模型 + 可关思考 + 支持工具调用，三项都满足。

### 5.5 API 细节

| 项 | 值 |
|---|---|
| API 地址 | `https://api.modelarts-maas.com/v2/chat/completions` |
| 鉴权 | `Authorization: Bearer $MaaS_API_KEY` |
| 协议 | **OpenAI 兼容**（`messages` / `stream` / `tools` / `tool_choice`） |

**我们关心的请求参数**：`model`、`messages`（system/user/assistant/tool 四种 role）、`stream`、
`tools`、`tool_choice`、`thinking.type`、`prefix`（前缀续写）。

**响应关键字段**：

| 字段 | 说明 |
|---|---|
| `choices[].finish_reason` | `stop` / `length` / **`tool_calls`** |
| `choices[].message.tool_calls[]` | `id` / `type`(仅 `function`) / `function.name` / `function.arguments`（**JSON 字符串**） |
| `choices[].message.reasoning_content` | 思维链（仅深度思考模型） |
| `usage.prompt_tokens_details.cached_tokens` | **缓存命中 token 数** ← 成本监控 |
| `usage.completion_tokens_details.reasoning_tokens` | 思考消耗 |
| `first_token_return_time` | **流式首 Token 返回时间** ← 延迟监控 |

**工具调用示例（官方，已验证）：**

```python
import requests, json

url = "https://api.modelarts-maas.com/v2/chat/completions"
api_key = "MAAS_API_KEY"          # ← 从环境变量读，不要硬编码

data = {
    "model": "openpangu-2.0-flash",
    "stream": False,
    "messages": [
        {"role": "system", "content": "You are a helpful assistant."},
        {"role": "user",   "content": "北京今天天气怎么样？"},
        {   # 上一轮 assistant 返回的 tool_calls 原样带回
            "role": "assistant",
            "reasoning_content": "...",
            "content": "",
            "tool_calls": [{
                "id": "call_df646371a477403597ad63c4",
                "type": "function",
                "function": {"name": "get_weather",
                             "arguments": "{\"city\": \"北京\", \"unit\": \"celsius\"}"},
            }],
        },
        {   # 我们执行工具后的结果回传
            "role": "tool",
            "tool_call_id": "call_df646371a477403597ad63c4",
            "content": "{\"city\": \"北京\", \"temperature\": 26, \"condition\": \"晴\"}",
        },
    ],
    "tools": [{
        "type": "function",
        "function": {
            "name": "get_weather",
            "description": "查询指定城市的实时天气",
            "parameters": {
                "type": "object",
                "properties": {
                    "city": {"type": "string", "description": "城市名称"},
                    "unit": {"type": "string", "enum": ["celsius", "fahrenheit"]},
                },
                "required": ["city"],
            },
        },
    }],
    "tool_choice": "auto",
}

resp = requests.post(url, headers={
    "Content-Type": "application/json",
    "Authorization": f"Bearer {api_key}",
}, data=json.dumps(data))
```

**对应 `04` §五 的 ReAct 循环：**

```
① 发 messages + tools      → ② 若 finish_reason == "tool_calls"
                                取出 tool_calls[].function.name / arguments
③ 校验 arguments（确定性层！）→ ④ 执行工具
⑤ 追加 {role:"tool", tool_call_id, content}
⑥ 再发一次                  → ⑦ finish_reason == "stop" 时返回最终回复
```

> ⚠️ **官方明确警告**：*"模型并不总是生成有效的 JSON，并且可能会虚构出一些您的函数参数规范中未定义的参数。
> 在调用函数之前，请在您的代码中验证这些参数是否有效。"*
> → 直接对应 `04` §1.4 的**确定性校验层**。

### 5.6 缓存命中优化（省钱关键）

官方原文：

> "上下文缓存旨在优化您调用模型服务的体验……**命中缓存的输入享有折扣优惠**。
> 这一机制**特别适用于多轮对话、工具调用**、角色扮演等场景。
> **无需额外配置**。用户发起请求时，系统会自动识别请求内容的**公共前缀**并进行缓存。"

**落地策略——把 prompt 设计成"稳定前缀 + 变化后缀"：**

```
[ 稳定前缀 —— 尽量长、尽量不变 ]           ← 会被缓存
  ① system 人设（04 §七 的沟通原则）
  ② 工具定义（04 §五 的 12 个 tools，JSON schema 很长）
  ③ 老人画像摘要（记忆里的 preference）
[ 变化后缀 ]                                ← 不被缓存
  ④ 最近 N 轮对话
  ⑤ 当前这一句
  ⑥ 召回的长期记忆片段
```

监控 `usage.prompt_tokens_details.cached_tokens`。

> ⚠️ 官方也提示"缓存命中率**不确定**"，且未命中时"首 Token 时延可能会有一定程度的增加"。
> → **缓存是成本优化，不是延迟优化**。延迟靠 `thinking.type=disabled` 控制。

> ✅ **好消息**：MaaS 是华为云产品，**代金券理论上可用**（Qwen/豆包必须自付）。
> 这坐实了双模型分工的合理性。

### 5.8 MaaS 的坑（汇总）

| # | 坑 | 应对 |
|:--:|---|---|
| 1 | **仅"西南-贵阳一"** | 跨区调用延迟需实测；或把应用也部署到贵阳一 |
| 2 | **必须先配 ModelArts 委托授权** | 开通第一件事 |
| 3 | **自动开通所有版本、不支持关闭** | 接受；靠管理 API Key 控制 |
| 4 | **`tool_choice` 因模型而异** | 需强制调用时换 DeepSeek/GLM |
| 5 | **GLM-5.3 无法关深度思考** | 实时场景不要选它 |
| 6 | **模型可能返回无效 JSON / 虚构参数** | 必须走确定性校验层 |
| 7 | **缓存命中率不确定** | 只作成本优化 |
| 8 | Token Plan 需专用 Base URL | 不要与按需计费 endpoint 混用 |
| 9 | API Key 泄露 = 持续扣费 | 见 `09` §六 |

## 六、双模型分工

```
┌──────────────────────────────────────────────────────────┐
│  语音层  →  qwen-audio-3.1-realtime-plus                  │
│  职责：全双工对话、VAD/smart_turn、流式 ASR + TTS          │
│  理由：华为云无对等产品（§二）；smart_turn 命中老人场景     │
├──────────────────────────────────────────────────────────┤
│  事务层  →  华为云 MaaS（openPangu）                       │
│  职责：事项抽取、多假设推理、工具编排、记忆整理             │
│  理由：① 赛题一"基于华为云产品"的技术栈体现                 │
│        ② 支持工具调用，承载 04 §五 的工具集                 │
│        ③ 代金券可覆盖                                       │
├──────────────────────────────────────────────────────────┤
│  后端  →  Python，部署在华为云 ECS（09）                   │
│  数据  →  华为云 RDS + Redis（赛题强制项）                 │
└──────────────────────────────────────────────────────────┘
```

**申报书可写的句子：**

> "系统的大模型推理层采用**华为云 MaaS（模型即服务）**，基于 **openPangu-2.0** 系列模型实现 Agent 的
> 工具调用与多轮推理；通过 `thinking.type` 参数在实时对话场景关闭深度思考以降低首 Token 时延，
> 并利用 MaaS 的**上下文缓存**机制（官方说明适用于多轮对话与工具调用场景）
> 优化长 system prompt 与工具定义带来的重复输入开销。"

—— 具体、可验证、有技术细节，比"我们用了华为云"强得多。

## 七、成本控制

| 措施 | 说明 |
|---|---|
| **开发期用便宜模型** | `qwen-audio-3.0-realtime-flash` 联调；只在演示/评测时用 `-plus` |
| **限制单次通话时长** | **5 分钟**上限，超时温柔收尾（`04` §三 的 `end_conversation`） |
| **服务端 VAD 前置过滤** | 静音不上行 |
| **按需启停会话** | 不聊天时**断开 WebSocket** |
| **本地 mock 优先** | 客户端开发全程用 `MockVoiceProvider`，不烧 token |
| **每日额度告警** | 在百炼控制台设预算告警 |
| **MaaS 侧** | `thinking=disabled` + 控制上下文 + **利用缓存前缀** |

> ⚠️ **代金券的坑**：华为云代金券**只能用于华为云**。
> 阿里云百炼 / 火山引擎**需另外付费**。这是真实的自付成本，必须先算清楚（`12` T-21）。

interface RealtimeVoiceProvider {

    fullDuplex: boolean;

    available: boolean;
    unavailableReason?: string;
  }>;
  connect(session: VoiceSessionConfig): Promise<VoiceConnection>;

| 实现 | 阶段 | 说明 |

| `MockVoiceProvider` | 演示 | 与 `07` §六 的 mock 规矩一致（必须带徽标） |
