# 06 · 客户端、家庭连接与通知

> 手机是核心入口，不是语音盒的附属配置端。产品目标见 [需求](../product/02-需求.md)；框架、平台和通道仍需实测，旧 RN／HMS 示例不视为已定实现。

## 一、老人手机端

### 1.1 日常主入口

- 清楚开启、结束和静音的语音会话，支持录放音并发、自然打断、补充和改口。
- 能查询今天安排、调整提醒、查看和纠正记忆，不要求填长表单。
- 不把“全双工”解释为全天监听；权限、录音指示和音频保留应易懂。
- 明确区分“听到了”“正在整理”“已经保存”“发送状态未知”。
- 支持只有老人一个账户的完整使用，不先要求绑定子女或设备。

### 1.2 管理入口

个人记忆与来源、提醒计划与单次反馈、共享对象与类别、保留／删除、通知权限和异常状态。敏感内容播放与共享遵守设置。

语音是低门槛主入口，不代表屏幕和可访问性可省略。误识别时可用文字或简短选项纠正，但不能强迫老人通过复杂表单弥补系统失败。

## 二、子女端不是工单首页

### 2.1 最近的生活

少量授权近况与老人愿意分享的原话，标时间、来源与 AI 整理属性。没有新内容不凑日报；不默认展示完整音频、私人记忆和健康细节。

原话片段需要独立授权、保留期限、合理截取和撤销处理；不以合成父母音色冒充真实片段。

### 2.2 下次聊什么

准备联系时回顾父母近期关注的事、愿意分享的回忆和系统内已知约定。线索可忽略，不形成待办，不自动发送。

只检索该亲属可见内容；私人记忆不能借“推荐话题”旁路泄露。不假装获取微信或外部电话历史。

### 2.3 双向的真实回应

子女主动发送自己的近况、文字或语音，按老人接收设置转达。AI 可以辅助草稿，但本人确认才发送，标明真实发送者；没有回应不编造已读、关心或承诺。

首版优先真实留言，不先做完整社交平台。电话和微信可继续承担实际联系；系统不知道的外部行为不能自动记成发生。

### 2.4 需要你参与

明确请求才提供接手、约时间、说明做不了和结果反馈。前台使用自然表达，后台保留严谨状态；分享不要求办结，邀请可以回应或婉拒。

不展示孝心排名、未关怀倒计时、家庭绩效或强制每日阅读红点。判断价值要包含“没有任务时是否仍帮助理解和联系”。

## 三、客户端技术取舍

| 方向 | 当前状态 |
|---|---|
| Android | 优先验证，不等于全部厂商和系统已支持 |
| Web／PWA | 可做原型、家庭界面和在线 Demo；音频、后台与推送逐平台验证 |
| iOS | 候选后续适配，签名、账号、APNs、音频与后台分别落实 |
| React Native／其他框架 | 待 PoC 后定案，先验证双向音频与打断，再评价开发成本 |
| 原生桥接／小组件 | 只有实际需要才引入，不因旧稿有代码就必须实现 |

若选 RN，核实版本、原生音频／推送插件、新架构兼容和事件链；不能未经验证断言必须自写 TurboModule。无论框架如何，权限、状态合法性与幂等由后端控制，不放在 TS／Kotlin 客户端作为唯一依据。

## 四、通知不是产品唯一载体

站内内容、真实消息、提醒计划、明确请求及发送任务持久化。通知只是入口；在线同步、手机系统通知、补充 Webhook 是不同通道。

| 内容 | 通知策略方向 |
|---|---|
| 普通近况 | 用户可配置频率，不每段聊天推一次，不强制催读 |
| 联系线索 | 联系前主动查询优先，主动推荐需可关闭并限制频率 |
| 真实留言／邀请 | 依接收设置提醒，不冒充已经回应 |
| 明确请求 | 通用提醒＋鉴权详情，接手与反馈单独记录 |
| 定时提醒 | 按已确认计划；后台、本地或远程实现分别实测 |

默认通知不携带健康、私密原话或完整聊天。通用内容也不能泄露“有一条拒绝分享的信息”。通知携带不直接暴露内容的标识，打开后重新认证授权；旧链接在撤销后不可读。

## 五、触达边界

1. JPush／HMS 为候选，按实际账号、客户端、厂商通道与配置实测，不承诺全机型可达。
2. 聚合推送不自动免除厂商资质、上架、签名与用户通知权限；门槛按具体主体核实，不泛化“学生一定拿不到”。
3. WebSocket 只提供连接存活时的在线同步，不能替代 App 被终止后的后台推送。
4. JPush 本次核对的 REST 平台列表不包含浏览器 Web Push，不能直接外推其他服务或所有浏览器永久不可行。
5. 通知消息、数据消息与系统后台限制按实际 SDK 验证，不能凭示意代码认定关闭 App 仍会展示。
6. Webhook 只补充获准的通用提示，不替代登录鉴权、站内内容和实际回执。

官方资料和语言／平台范围见 [08](08-外部依赖核查.md)。厂商支持列表与本产品实测清单是两回事。

## 六、提醒执行与跨端同步

调度以服务器计划和版本为依据。若手机实现本地提醒，必须处理重复调度、时间变更、取消、重装、离线和恢复，发布已验证范围；未实现不得写“离线照常可靠”。

多端更新与收到新版本不同，服务受理与终端展示不同。恢复联网后同步最新状态，不重放过期通知或过期用量播报。

## 七、状态与测试矩阵

- 发送任务已持久化／渠道受理／可靠送达（如可得）／失败／未知分别记录。
- 通知点击、已读、留言回应、请求接手、外部真实联系分别记录。
- 失去权限后旧通知、缓存预览、原话链接、话题结果均要失效或受限。
- 按平台／机型／系统／权限／网络记录前台、后台、进程终止、重启与弱网结果。
- 验证没有待办、空近况、亲属不回应、拒收和取消规则，不只测正常接单。
- 保护性频控不擅自改变用药安排；无人反馈不等于漏服或危险。

框架和通道见 T-17／67／76／80／81，隐私与数据期限见 T-66／82，定义和指标见 [10](10-评测方案.md)。当前没有客户端实测通过证据。
