### 1.3 三大赛题（报名时三选一，**独立评审、独立晋级名额**）

#### 赛题一：基于华为云产品打造 AI 创新应用 ★开放型

- **类型**：开放型赛道，**不限应用场景**（休闲娱乐 / 办公助手 / 行业应用 / 生活服务）
- **技术要求**：
  - 必须使用 **华为云码道 CodeArts 代码智能体** 进行开发
  - 基于已有**智能体和 Skills**，关联 **RDS、Redis** 等华为云服务
  - 完成应用**在华为云上的部署**，确保作品**可在线运行**
- **评分侧重**：**创新性占 60%（初赛）/ 40%（中国区总决赛、全球总决赛）**
- **开源要求**：入围总决赛需开源
- **官方建议原话**："从小切口入手，打造能实际运行的系统，优于宏大的概念设计"

#### 赛题二：基于华为云 AgentArts 智能体开发平台的 Agent 设计和应用

- **技术要求**：基于 **AgentArts**（企业级一站式智能体构建与运营平台，可视化低代码）构建 AI Agent，**提交可运行的应用**
- **应用方向**（官方列举）：行业赋能型 / 效率提升型 / 创新探索型（多 Agent 协同、自主决策、持续学习）/ **生活服务型（智能家居、健康管理、出行规划）**
- **提交内容**：作品简介、创意点、团队介绍、技术方案、面向的行业问题 / 落地场景、**作品 demo 视频**
- **评分侧重**：实际可运行、**用户体验佳且易用**、精准解决生活生产领域具体问题、具备创新性与应用深度
- 参考：<https://www.huaweicloud.com/product/agentarts.html>

#### 赛题三：基于华为 ModelEngine + Nexent 打造可进化决策智能体

- **技术要求**：ModelEngine + Nexent
- **主题**：会进化、会决策的智能体
- **特征**：技术门槛最高（涉及模型部署与推理链路）
- 官方宣传口径："把想法讲清楚、把场景想透彻"

### 1.4 AgeGuard 与三赛题的匹配度

> ✅ **已决议（2026-10-14）：报赛题一。**

| 赛题 | 匹配度 | 理由 | 主要风险 |

| **赛题一** ✅**已选** | ★★★★☆ | 开放型赛道，场景不限；AgeGuard 是完整的 AI 应用（生活服务场景）；架构自由度最高 | 必须整体迁到华为云（CodeArts + RDS/Redis + 云上部署）；**不兼容 HarmonyOS 本地路线** |

## 二、大学生创新创业训练计划（大创）

### 2.1 三级体系与项目类型

```
国家级（国创计划） → 省级 → 校（院）级
项目类型：
  ① 创新训练项目   → 产出：创新性研究项目设计、研究报告、学术论文、专利
  ② 创业训练项目   → 产出：商业计划书、可行性研究、企业模拟运行、创业报告
  ③ 创业实践项目   → 产出：实际注册公司 / 真实运营（需企业导师）
```

> ✅ **已决议（2026-10-14）：大创报创业训练项目。**
> 产出物为 **商业计划书 / 可行性研究 / 企业模拟运行 / 创业报告**，而非研究报告。
> → 商业计划书所需的市场/竞争/财务分析尚未撰写，记为 `08` 缺陷 C14。

AgeGuard 目前是**概念方案，未注册公司、无真实运营**，因此**不能报创业实践项目**。因此选**创业训练项目**。

### 2.2 政策口径（对选题有利）

教育部《关于开展国家级大学生创新训练计划立项和结题验收工作的通知》明确：

> 重点支持项目"面向世界科技前沿、面向经济主战场、**面向国家重大需求**、**面向人民生命健康**"，鼓励围绕基础学科以及新工科、**新医科**、新农科、新文科等关键领域开展创新实践。

**养老 + 健康**属于"面向人民生命健康"，是**大创重点支持方向**。这是 AgeGuard 在大创赛道的天然优势，应该在申报书中明确对应这一政策条款。

> ⚠️ 国家级立项通知通常在**每年 3 月**发布，各校预申报多在 **3–5 月**。2027 年度项目需在 2027 年春季前完成选题打磨。具体时间以本校教务处通知为准。

### 2.3 大创的隐含要求（与 ICT 赛不同）

| 维度 | ICT 创新赛（赛题一） | 大创（**创业训练项目**） |
|---|---|---|
| 核心考核 | 创新性（60%/40%）+ 可运行系统 + 商用落地潜力 | 商业计划书 + 可行性研究 + 团队角色分工 |
| 必须有 | **华为云 CodeArts 开发 + 云上部署 + 在线可运行** | **指导教师**、商业计划书、企业模拟运行记录 |
| 产出物 | 代码 + demo 视频 + 答辩 PPT + 开源仓库 | **商业计划书 / 可行性研究报告 / 创业报告** |
| 时间跨度 | 约 8 个月（2026-09 → 2027-05） | 通常 1 年（含结题验收） |
| 团队 | 3 学生 + 1 教师 | 通常 3–5 人 + 指导教师（可同一套人马） |

## 三、双轨策略：同一项目如何同时服务两个赛事

**核心矛盾**：ICT 赛要"能跑的 AI 应用"，大创创业训练要"商业计划书 + 可行性研究"。

**处理方式 —— 一个内核，两种包装：**

```
                      ┌─────────────────────────┐
                      │   同一个核心技术内核      │
                      │  AgeGuard 关怀协作 Agent  │
                      └───────────┬─────────────┘
                                  │
          ┌───────────────────────┴───────────────────────┐
          ▼                                               ▼
  【ICT 创新赛 · 赛题一】                          【大创 · 创业训练项目】
  关键词：AI 应用、可运行、创新性、云原生              关键词：需求、市场、商业模式、可行性
  · CodeArts 代码智能体 + RDS/Redis + 云上部署     · 行业痛点 + 目标市场测算
  · 双端可运行 App + 公网可访问地址                · 竞品分析 + 差异化定位
  · Agent 工具调用 / 多假设推理 / 证据分级          · 商业模式 + 收费/合作方式
  · demo 视频 + 答辩 PPT                          · 财务预测 + 团队与分工
  · 交付：在线系统 + 开源仓库                       · 交付：商业计划书 + 可行性研究报告
```

**必须避免（对应红线 R7）**：两份材料不能是同一份文档改标题。差别应体现在：
1. **大创侧重"为什么值得做"**（市场需求、竞品差异、商业模式、可行性）
2. **ICT 赛侧重"做出来了什么"**（系统、创新点、演示、技术深度）

> 注：用户访谈与可用性测试（`07`）仍然要做——它是商业计划书里「市场需求验证」的证据，
> 而且 ICT 赛的「商用落地潜力」也需要它。

**建议的时间线整合：**

| 时间 | ICT 创新赛 | 大创 |
|---|---|---|
| 2026-10 ~ 11 | 定赛题一、报名、搭 CodeArts + 华为云环境 | 定商业模式、找指导教师 |
| 2026-11 ~ 12 | 完成 MVP，部署到华为云，提交初赛材料 | 申报校级项目，写市场与竞品分析 |
| 2027-01 ~ 03 | 完善系统，准备中国总决赛答辩 | 用户访谈 + 可用性实验，完善商业计划书 |
| 2027-03 ~ 05 | 全球总决赛（如晋级） | 财务预测 + 可行性研究报告定稿 |
| 2027-06 ~ | 开源、维护 | 结题验收（企业模拟运行记录） |
