# AgeGuard：自然交流、长期记忆与家庭连接的老人生活助理

> 本文是产品方案与交付计划，不是已实现功能清单。本轮用户澄清后的价值主线以 [product](../product/README.md) 为准，替代旧硬件优先及工单中心口径。

## 一、一句话介绍

AgeGuard 让老人通过手机自然交流，借助全双工语音与并行 Agent Loop，记住允许保留的重要生活信息，把确认过的安排变成未来提醒，并在授权下帮助家人了解近况、延续交流和参与具体帮助。

**手机即可使用。** 自建或其他品牌的人体存在传感器、智能开关等只是可选情境来源；语音盒、药盒不是必备项。

## 二、用户与问题

老人有自己的兴趣、习惯与分享意愿，不只是被照护对象。部分家庭中，老人愿意发送很长的语音，子女受工作和听取场景限制，难以逐条理解与记住。这既是信息处理负担，也包含“想和你说说话”的关系需要。

优先服务能自主表达、理解基本授权，但不喜欢复杂数字工具、希望获得记事与生活辅助的老人。独居、患病、子女异地或已购硬件都不是全部必要条件。没有子女加入，老人也应独立受益。

| 角色 | 核心价值 | 边界 |
|---|---|---|
| 老人 | 自然交流、跨次记忆、日常提醒、自主选择 | 不默认被监测、画像或全部共享 |
| 子女 | 理解生活、联系前回顾、真实回应、具体协助 | 不是全部私人档案的管理员 |
| 其他亲属 | 按授权参与联系与帮助 | 亲属关系不自动产生权限 |

这些问题仍需访谈与对照验证，不将长语音观察当普遍统计，不把普通遗忘当医疗诊断。

## 三、产品的两条相互连接的主线

### 3.1 对老人本人：聊过的事情以后仍有用

```text
自然闲聊／补充／改口
       ├→ 允许保留的重要信息 → 个人长期记忆 → 下次接着聊、纠错或删除
       └→ 生活安排候选 → 确认／有效预授权 → 持久化定时任务 → 执行与反馈
```

交流本身有价值，不要求每轮产生任务。“养鱼”“不喜欢晚上被普通提醒打扰”可以作为个人背景；“平常周末换水”不自动变成永久计划。

### 3.2 对家庭：更容易听懂，也更容易接着聊

```text
老人允许分享的内容 → 授权投影
                    ├→ 少量近况＋愿意分享的原话
                    ├→ 联系前回顾、可以接着聊的话题
                    └→ 明确求助 → 接手／协商／反馈
子女本人发送的真实留言 ─→ 按接收设置转达给老人
```

子女端不是三个待办队列。没有明确请求时，也能因为了解生活、准备联系和真实回应而有用；不要求每日阅读，不设置孝心评分。

AI 不冒充子女、不自动代发关心，不假装知道未接入的微信或外部通话。减少的是整理负担，不是家庭交流本身。

## 四、核心实现与可靠性

```text
老人手机 ↔ 后端语音会话／音频适配 ↔ 语音模型
                   │ 轮次事件、改口、取消
                   ▼
            并行 Agent Loop
       记忆候选／检索／提醒／共享候选
                   │
                   ▼
       确定性业务服务：身份、授权、版本、幂等、确认
          ├ RDS：个人记忆／修订／计划／共享内容／消息／请求
          ├ 持久化调度与发送记录 → 手机提醒／家庭通知
          └ Redis：会话／缓存／限流等辅助

可选传感器 → 认证／型号能力／时间质量／事件持久化 → 获准的情境辅助
```

这是逻辑设计，框架、音频协议、模型与客户端尚需实测。全双工与 Agent 并行是核心目标，不等于选定某供应商、绑定某框架或全天监听。

### 4.1 并行不等于无约束自治

语音交互继续时，Agent 可以整理信息与执行受控工具。不同结果经统一输出协调，避免重复发声、迟到结果覆盖用户更正或“还在保存却说已完成”。

业务副作用经后端校验，不由提示词代替；确认可来自经认证会话的明确语音或界面动作，须对应动作与版本。具体架构见 [04](04-Agent架构.md)。

### 4.2 个人长期记忆的三个要求

1. 保存可靠：持久化、重试幂等、恢复与备份，关键内容不只存易失会话。
2. 理解可靠：来源、时间、候选／确认与修订，不能把摘要当新事实。
3. 共享合适：私人记忆与亲属可见投影分开，撤销、纠错和删除覆盖派生内容。

“全局”表示该用户跨会话可用，不是所有人混用，不是家属默认可读，更不是永久保存全部原文。

### 4.3 提醒与通知

定时任务由确定性调度执行，不靠模型持续猜测时间。计划、单次执行、渠道回执与用户反馈分开。重启不丢任务，重试不重复，取消或新版本不再执行旧任务。

手机后台与网络会影响触达；已保存、渠道受理、展示、打开、本人知晓分别记录。不承诺急救级必达。分段语音可降级，但必须标识，不能算全双工完成。

## 五、可选硬件与来源边界

自建和第三方方案都可研究。选择依据是有无设备对照中是否少输入、少打扰、体验更好，而不是为了增加展示数量。

- 存在传感器只提供特定区域的存在／活动，不一定知道是谁。
- 智能开关只提供其实际状态和事件，不能证明本人已完成某项家务。
- 药盒开合不证明具体取药、吞服或漏服。
- 离线、旧数据和没有记录不能证明危险或安全。
- 接入权限、SDK 语言／平台、字段、型号、时效与费用逐项核查，不承诺任意品牌通用。

详情见 [13](13-产品形态与可选硬件.md)；SDK 与官方来源见 [08](08-外部依赖核查.md)。

## 六、边界与非目标

首版不默认覆盖代理授权、监护认定、专业医疗端、可靠安全监护和急救。不诊断、不开方、不自行改药；用药提醒依赖有来源、已核对的现有安排，不由闲聊或搜索结果生成用量。

不读取未授权聊天，不将私人记忆自动家庭共享，不用假回应制造被关心感，不把家属已接手或事项已办结等同于老人满意。

当前外部条件、战略取舍、实际系统问题分别记录在 [01](01-定位与边界.md) 与 [12](12-风险与待验证.md)，不能用其中一类掩盖另一类。

## 七、里程碑

| 阶段 | 目标 | 完成证据 |
|---|---|---|
| M1 自然交流＋并行处理 | 手机真实双向音频、打断／改口与后台 Agent | 真实会话、时间线、失败与取消测试 |
| M2 可靠记忆＋主动提醒 | 来源、跨会话召回、纠错／删除、版本、持久化调度 | 重启、重试、过期、恢复与隔离结果 |
| M3 家庭连接 | 授权近况／原话、联系前回顾、真实留言、明确求助 | 无待办情境、权限撤销与双向使用证据 |
| M4 价值评测＋云端交付 | 与现有方式对照，开发、部署和复现 | 用户与家庭反馈、真实失败、在线 Demo 和复现材料 |
| 可选分支 | 存在／开关等传感器或其他交互硬件 | 逐型号接入、有无设备增益和限制清单 |

阶段可交叉推进。访谈与子女端原型从早期开始，不等完成全后端才验证核心价值；设备分支不阻塞主线。

## 八、评测与证据

同时测自然交流、长期记忆、任务可靠性、隐私，以及子女理解负担与老人感受。不能只测任务办结率、摘要压缩率或每日活跃。

重点对照“家庭原有微信／电话＋闹钟”“普通无长期记忆聊天”“纯摘要视图”和“近况＋来源＋话题＋真实回应”。不编造提升数字，不将合成数据算真实家庭，不将临床结果作为已证实效果。见 [10](10-评测方案.md)。

## 九、赛事与商业衔接

赛事方向仍为第十一届华为 ICT 创新赛赛题一，大创为创业训练。已有官方核查记录、评分和赛程见 [00](00-赛事要求.md)，阶段截止须复核；2026-12-01 仅既有内部上云目标。

CodeArts、已有智能体／Skills、华为云资源与在线 Demo 有实际职责和证据；KooCLI、两个自定义 Skill、IoTDA 或硬件数量不是独立必选指标。开发智能体不等于产品运行时 Agent。

商业上仍需回答付费者、持续使用理由、可服务人群、语音与云费用、配置和支持成本；不把老龄人口总量当可触达市场，不把子女愧疚感当支付意愿。

当前只有设计文档，没有应用／固件／端到端通过证据。具体模型、协议、框架、后台提醒范围、共享默认值、原话保留、样本和负责人均待实测或决策，集中见 [12](12-风险与待验证.md)。
