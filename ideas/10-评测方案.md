# 10 · 评测方案：连续帮助与真实连接

> 当前仅计划，未取得用户、设备或端到端结果。不能以全双工术语、任务办结、摘要压缩率或日活代替用户价值。产品假设见 [需求](../product/02-需求.md)。

## 一、需要分别回答的问题

1. 老人是否能自然交流，长表达、停顿和改口是否被接住？
2. 重要信息是否正确理解、可靠保存，并在下次有用？
3. 提醒是否来自明确意愿，能可靠执行、修改、取消与恢复？
4. 子女是否更容易理解父母的生活、准备联系、作出真实回应？
5. 减负是否以老人感到被忽略、被监测或真实联系减少为代价？

“保存可靠”“理解正确”“共享合适”各自测量，不能合并成一个“记忆准确率”。

## 二、数据与对照

### 2.1 分开三类证据

- **合成场景／脚本音频**：可控测试轮次、来源、状态和故障，不冒充真实老人语料。
- **目标用户可用性**：观察独立操作、理解、纠错与授权，不用年轻代理用户替代实际可用性证据。
- **真实家庭试用**：经同意持续观察表达、使用与联系；主观感受、系统内日志、外部交流自报分开报告。

调试与最终评测场景隔离；同一批样例反复优化后不能报告成泛化表现。样本、时长、阈值、招募、补偿与必要伦理要求在 T-68／69／79／80 确定。

### 2.2 对照组合

| 对照 | 目的 |
|---|---|
| 家庭原有微信／电话＋闹钟或日历 | 比实际现有习惯是否更有用，而非比“什么都没有” |
| 普通单次聊天／无长期记忆 | 验证跨次记忆的增益 |
| 只有 AI 摘要的家庭视图 | 验证原话、话题和真实回应是否有额外价值 |
| 近况＋来源＋联系前回顾＋真实回应 | 验证关系入口，而不只测任务队列 |
| 同一核心流程有／无可选设备 | 独立验证传感器是否减少输入和打扰 |

同内容、相近任务与使用条件比较，记录学习顺序、熟悉度和研究者提示。不能将对照中的“全部语音长度”直接当作本产品省下的真实时间。

## 三、核心指标

编号为本轮评测口径，旧硬件优先指标不再沿用原含义。

| ID | 指标 | 测量与解释 |
|---|---|---|
| E-01 | 自然对话与打断 | 实际双向录放音、打断生效、误打断／误截断、延迟分布、用户困难 |
| E-02 | 长表达的信息覆盖 | 脚本标注的重要事实／意愿／关系内容的准确率与召回，含约 60 秒及更长表达 |
| E-03 | 并行处理与竞态 | 对话继续时后台处理的时间线；改口、取消、两路事件重复与漏处理 |
| E-04 | 持久化和恢复 | 写失败不假报成功；提交后崩溃、重复投递、重启与备份恢复的丢失／重复范围 |
| E-05 | 跨会话召回与来源 | 清空会话后，记忆相关性、来源保真、时间范围和跨用户隔离 |
| E-06 | 记忆整理的语义保持 | 去重是否保留关键背景／关系内容，是否将临时信息固化、把习惯变计划 |
| E-07 | 纠错、删除与撤销传播 | 原文、候选、记忆、摘要、话题、原话链接、索引、发送任务和恢复后的实际状态 |
| E-08 | 提醒计划与单次反馈 | 创建、时区、修改、取消、一次完成、周期边界、旧版本失效 |
| E-09 | 调度与通知可观测性 | 预定／触发／受理／可靠送达／展示／未知分别计时计数，不把受理率当送达率 |
| E-10 | 授权与最小共享 | 直接访问、生成上下文、摘要／原话／话题／通知、撤销及旧链接的越权测试 |

权限、误用药安排或错误高影响副作用一经发现，应阻断对应真实试用并修复。报告通过的具体范围，不以“没发现”声称系统永远无漏洞。

## 四、子女端与关系价值指标

| ID | 指标 | 不能用什么替代 |
|---|---|---|
| E-11 | 近况理解与内容保真 | 阅读更短不等于理解更正确；记录遗漏、歪曲与需要回听 |
| E-12 | 原话的意义与负担 | 是否保留父母想分享的重点／温度，是否增加打扰；截取失真与权限分别测试 |
| E-13 | 联系前回顾的可用性 | 话题相关、有依据、自然且不泄露；点击话题数不等于有用 |
| E-14 | 真实双向回应 | 发送者与草稿清楚，愿不愿意回应、接收是否合适；自动模板发送不算真实参与 |
| E-15 | 子女的信息处理负担 | 同等理解目标下的时间、操作、遗漏与主观负担，不只测摘要压缩率 |
| E-16 | 老人的表达意愿与感受 | 是否愿意继续分享，是否感到被听见、自主或被外包／被监视，不由子女代答 |
| E-17 | 实际家庭交流 | 系统内消息与外部交流自报分开；内容延续、自然程度、质量感受与频率一起观察 |
| E-18 | 无待办情境价值 | 没有明确请求时，是否仍因近况、准备联系或留言受益；不要求每天打开 |
| E-19 | 明确求助的协作 | 接手、协商、实际结果与老人可选感受分开；办结不等于关系改善 |
| E-20 | 可选设备的边际价值 | 同一情境下输入、打扰、误解与维护负担；设备数和事件数不是价值 |

### 避免“减负成功、关系受损”

试用同时收集老人和子女反馈。子女少听语音，但老人减少表达、感到被敷衍，不能直接报告整体成功。

对话题线索促成的真实联系，保留自报来源与样本限制；短期、小样本试用不能归因于产品改善长期关系，更不宣称减少孤独或临床收益。

## 五、必测场景组

- 长闲聊同时有生活背景、家庭回忆、提醒与求助，不只保留任务。
- 纯闲聊无动作，老人拒绝记忆／分享，近况为空或子女无待办。
- 播放中插话、长停顿、附和、改口；Agent 旧结果晚到。
- “这次做完”与“以后不需要”不同；习惯表述不自动启用计划。
- 联系前回顾和原话链接不能越过授权；子女自己私人资料不自动给老人。
- 子女只保存 AI 草稿、不发送；无人回复不伪造回应或承诺。
- 保存失败、提交后崩溃、重复事件、取消／过期、通知未知、App 终止和手机重启。
- 用药自报与设备观测不同，无反馈不等于漏服，系统不建议补服。
- 可选设备离线、乱序、抖动和冲突不制造安全结论。

详细故事见 [典型使用场景](典型使用场景.md)，设备分支见 [13](13-产品形态与可选硬件.md)。药盒只用空盒／虚构资料，不安排真实漏服、补服或重复服用。

## 六、分阶段执行与报告

1. 开发前做需求访谈与子女端概念测试，识别不适用家庭和关系风险。
2. 手机 PoC 验证双工与并行，再测跨次记忆、调度和故障。
3. 核心可用性测试后，再开展获准家庭试用；不等待硬件采购。
4. 无设备核心通过后，按独立增益验证设备分支。

结果逐项报告样本／任务数、数据集版本、平台、方法、日期、分母、错误、人工干预和限制。未测写计划，不填示例百分比冒充成果，不引用不存在的 `eval/` 目录作为已交付。

原始私密语音、聊天、处方和家庭轨迹不默认公开；开源合成场景、获许可且适当脱敏的资料与可复现脚本。研究退出、删除和敏感内容处理在真实采集前确认。

## 七、发布判定

核心软件、权限／用药边界与真实通知范围应有证据；子女端至少包含无任务也有用的验证。部署证据不能替代价值证据，硬件分支结果不能替代全双工与记忆证据。

验证任务对应 T-68／75～83；未测指标不预设高准确率，具体数值目标在样本、基线和风险范围确定后制定。
