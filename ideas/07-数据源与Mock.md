# 07 · 数据源、真实设备与 Mock

> 当前路线见 `13`。**商用穿戴／家居接口受限，不代表自制传感节点不可行。**
> 本文件写设计与演示规则，不把端口设计、文档研究或模拟实现说成已连通的设备能力；外部事实见 `08`。

## 一、一期必须有的真实闭环

- 语音盒：实际按键、录音、播放、当前上下文确认／取消和后端反馈。
- 药盒节点：真实稳定开合事件、设备身份、时间质量、重复投递与重连补传。
- 授权协作：真实身份和资源权限，事项、提醒、人员反馈与通知独立持久化。

Mock 可验证开发链路、错误场景和未接入的商用数据，但**不能替代两类硬件的最终验收**。网页上的按钮、LED 随机闪烁和传感回放不算真实设备功能通过。

## 二、数据源与证据对象

| 数据来源 | 一期职责／扩展定位 | 语义边界 |
|---|---|---|
| 老人主动表达／自报 | 需求和本次反馈 | 表达不清先澄清，自述不等于独立测量 |
| 亲属录入／跟进 | 获授权协助记录、对照来源、反馈处理 | 不因家庭关系自动获权；家属核对不等于专业审核 |
| 语音盒交互事件 | 录音、播放执行、确认／取消 | 设备身份不等于本人；播放完不等于知晓 |
| 自制药盒事件 | 容器开／关、设备状态与活动片段 | 不证明具体药、吞服、漏服或危险 |
| 药品／安排来源 | 按需录入标签／原件文本及版本 | 通用说明不是个体医嘱；资料不明不启用具体用量播报 |
| AI 提取／OCR | 待核对候选 | 不是独立事实来源，不能自动确认或启用 |
| 商用穿戴测量 | 条件性后续目标 | 主体、审批、授权、设备、接口和时效分别核实 |
| 商用家居事件 | 条件性后续目标 | 未核实通用通路时明确不可用，不泛化所有厂商永不开放 |
| Mock／合成数据 | 调试、回归、异常和降级演示 | 显式标注，不能混入真实效果统计 |

## 三、接入适配设计

| 端口／服务方向 | 职责 | 实施要求 |
|---|---|---|
| `DeviceEventSource` | 规范化语音盒／药盒事件与来源 | IoTDA 接入、认证、结构校验、幂等入库和时钟质量；不是通用健康测量 |
| `ManualSource`／`RelativeReportSource` | 人员录入／反馈 | 受认证人与资源权限约束，保留原文及所指对象的不确定性 |
| `MedicationSourceRecord` | 有来源的药品／安排材料 | 采集最小范围、来源／核对／版本和删除，不自动抓取整份病历 |
| `VitalSource` | 可选健康指标适配 | 只按实际字段和授权声明能力，不默认当前具备真实适配器 |
| `EnvironmentSource` | 可选商用家居适配 | 不可用时显式降级；自制药盒不依赖它 |
| `TransportChannel` | 可替换传输路径 | 当前设计为 MQTTS／HTTPS；星闪只留条件性扩展 |
| `NotificationChannel` | 主推送、补充 Webhook 等 | 通知状态单独记录，不与设备上报转发混为一种 Webhook |

这些是逻辑端口／对象建议，不是仓库已有代码清单或已支持设备列表。更换适配器仍可能需要权限、字段、时间语义与集成测试，不能承诺“换一行配置即可接任何设备”。

## 四、不可用与降级

- 返回不可用及原因：未接入、权限不足、设备离线、版本不支持或时间过期，不造数值占位。
- 来源发生时间与接收时间分开；不可靠或未知的发生时间保留空值／时钟质量。
- 设备离线不等于没有开合；新到的离线旧事件不当成当前动作触发提醒。
- 多来源冲突保留原记录并澄清，不以设备标签自动覆盖自报。
- 计划更新和设备同步是两件事；旧音频／任务的失效边界见 `13` §六及 T-61／65。

## 五、能力声明与事件处理

适配器声明至少表达：真实／模拟、来源与设备类型、具体观测能力、平台／固件适用范围、时间质量、字段缺失及不可用原因。

业务处理分层：**传感去抖 → 传输幂等 → 真实事件 → 活动片段 → 计划关联 → 授权跟进**。各层不能互相代替：

1. 重传使用相同事件标识；设备＋事件标识唯一入库。
2. 去抖窗口按传感器安装和实测确定，不用过长窗口吞掉真实动作。
3. 原始稳定事件保留真实多次开合，片段只合并展示／减少打扰。
4. 一个总盖子不能确定容器中哪种药，更不能把一次动作关联到全部药物计划。
5. 调试边沿、设备事件和展示摘要的保留期限分别确定，不默认永久存储。

具体契约与测试见 `13` §四～五及 T-57／59。

## 六、Mock 与演示规则

| 项 | 要求 |
|---|---|
| 类与配置 | Mock 类明确命名；fixture、版本和启用入口与业务事实分开 |
| 数据内容 | 合成／空盒脚本，不伪造真实医院、医生、处方或老人服药行为 |
| UI | 每条模拟来源可辨；混合真实与模拟时按来源标记，不能只放一个容易漏看的总开关 |
| PPT／视频 | 说明实时采集、录制回放、模拟事件分别是哪部分 |
| 指标 | 真实硬件、仿真、合成场景和真实试用分开统计 |
| 开源 | 提交无隐私 fixture；真实处方／聊天不得作为默认公开评测集 |

推荐开场说明：

> 当前演示哪些步骤来自真实语音盒、哪些来自真实药盒、哪些是合成异常用例，会逐项标明。开合传感器只证明容器动作，不能核验吞服。商用手表／家居未接通的部分仅作为显式设计回放，不计入已交付能力。

这段话用于说明证据，不得在硬件未完成时伪称其已经真实接通。

## 七、项目书分层写法

| 状态 | 可写内容 | 不可写内容 |
|---|---|---|
| 已决策 | 语音盒＋药盒节点为首版主线，完整后端保留 | “两类硬件均已稳定运行” |
| 官方文档支持 | 指定板卡／SDK 提供哪些语言、硬件接口和通信能力 | “支持 MQTT 所以已经支持完整语音” |
| 实测通过 | 指明板型、版本、接线、账号、测试路径、结果与失败范围 | “换任意设备也可直接使用” |
| 未接入／模拟 | 数据来源、限制范围、替代和未来前提 | 把 Mock 截图说成真实健康／家居采集 |

不把“存在一个接口设计”写成“适配器已经实现”，也不把当前个人账号的限制写成所有合作主体永久无路可走。

## 八、来源标签

沿用 `04` §11.2 的 E 标签仅作来源分类；AI 候选和模拟另标。

| 类型 | 界面写法示例 |
|---|---|
| E1 自述 | “本人自报本次已服药” |
| E2 亲属反馈 | “亲属补充：刚才在整理药盒” |
| E3 设备 | “药盒检测到开启，发生时间不可靠，接收于……” |
| 有来源资料 | “家属对照原标签核对，来源版本……”；不自动称专业审核 |
| AI／OCR 候选 | “待核对提取结果” |
| 模拟 | “合成测试事件，非真实家庭活动” |

“设备记录＋本人自报”也不会升级成“已核验服药”。来源与访问权限分开管理。
