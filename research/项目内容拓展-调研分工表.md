## 一、分工原则

1. **分调研问题与可检查产物，不只分“前端／后端／硬件”。** 不懂 Agent 的队友可负责用户经历、交互走查、Android 权限、BLE、雷达、资料与对照测试。
2. 每包填一位主责和一位不同的复核人；可以一人主责多包，但不能所有实现、评测和复现都压给同一后端同学。人少时分批启动。
3. 资料、账号可用、设备可用、项目构建、真机读数、端到端与用户价值分别验收。没有条件时交付明确阻塞和可选路线，不虚构成功。
4. 真实访谈／录音／家庭试用前先落实同意与退出；账号付费、设备购买和云资源创建要事先批准。本表不是采购或收费授权。
5. 医学和法律资料搜集可由队友做，但不能把队友自行判断当专业批准。涉及病痛、紧急例外与监护承诺，需另找合适的专业复核资源；未落实时只做低风险、合成或回放研究。

## 三、每个工作包具体查什么、交什么

### R01 · 用户、竞品与付费价值

- **查什么**：老人首次为何打开，是否愿意与 AI 交流；家人是否需要联系前回顾；目前微信／电话＋闹钟哪里不够用；谁安装、谁维护、谁付费。
- **资料与方法**：S26、S27、S29；分别访谈老人和家人，追问最近发生的经历，保留“不需要”的反例。未取得真实访谈条件时，可交概念测试计划，不编造结果。
- **交付**：一页用户情境与待验证假设；至少覆盖原有工具、通用 AI、老人陪伴产品、家庭协作产品的竞品矩阵；老人独立使用和家庭参与两种价值路径；付费理由与反对理由。
- **通过条件**：每条竞品事实有日期与来源，未核能力写未知；没有把老人表达当噪声、把子女愧疚当支付、把赠送安装当留存。说清下一步最值得证明的一个差别。
- **依赖／输出给谁**：先落实 R08 的采集前置；为 R03／R04 原型和 R09 对照提供真实问题，而非只给市场规模。

### R02 · 记忆质量与评测门禁

- **查什么**：候选与确认如何区分；新增、更新、冲突、去重、期限、删除和恢复；评测模型在哪些错误上有帮助，在哪些会共同犯错。
- **资料与方法**：S22、既有 Agent／记忆规格；先准备合成且人工标注的典型与对抗用例，覆盖否定、改口、时间变化、错人、敏感内容、无任务和删除后重处理。用例数量按资源定，不当作已完成评测。
- **交付**：记忆字段与写入规则草案、审查 rubric、带来源的样例与预期动作；规则／单模型／加入审查的质量、耗时和费用比较设计，条件允许再跑结果。
- **通过条件**：不能用总分覆盖错误共享、误用药或跨用户污染；评审需与人工标签核对，说明分歧和偏差；不写“永不劣化”。删除记录不因回滚复生。
- **依赖／输出给谁**：与 R04 统一记忆／安排／共享对象；给 R09 可重跑的测试与费用字段。模型账号和付费实验先审批。

### R03 · 主动关怀与消息策略

- **查什么**：天气、衣物、可信季节信息、真人子女关切、既有用药安排、不适回访、未处理卡片、长期未互动和沟通风格分别如何触发与停止。
- **资料与方法**：S19–S21、S23、S28；先以虚构记录走查，不采集真实病史；天气走当前 API 文档，不照抄已提示弃用的 v7 教程。
- **交付**：按消息类型列触发依据、对象、来源／有效期、渠道、安静时段、频率、未回应、取消／过期处理的策略表；若选天气 API，补语言／协议、认证、账号、配额、费用与归因证据。
- **通过条件**：无答复不等于同意；普通关怀与用药计划分开；没有伪造子女留言、个人疾病预测和补服建议；能解释为什么此时出现这条消息，以及怎样不再出现。
- **依赖／输出给谁**：健康相关脚本先给 R08 专业待审；发送条件交 R04／R05，真实成本字段交 R09。模型自然措辞与确定性触发职责分开。

### R04 · 分享、家属建议与多人协作

- **查什么**：保留、执行、分享、求助是否分权；家属提议何时生效；接手与转让如何确认；撤销什么会影响谁；空近况与无待办是否仍有价值。
- **资料与方法**：S26–S27、本地交互／对话原型；至少走查老人拒绝、未回答、改口、转让拒绝、多人并发和授权撤销。
- **交付**：权限表和状态迁移表；分享确认、家属建议、接手／转让、老人反馈的界面或纸面脚本；确认与拒绝的错误理解记录。
- **通过条件**：目标亲属未获权限不先泄露详情；转让未接受不假称已接手；只对明确求助办结；现有原型的私人换水安排出现在子女话题中的授权缺口需明确修正方案。
- **依赖／输出给谁**：与 R02 统一对象，与 R03 统一未处理策略，与 R05 统一通知内容；给 R09 两端可验证流程，不交给后端自行猜规则。

### R05 · Android 通知、系统日历与使用统计

- **查什么**：通知、全屏意图、精确闹钟的不同权限／分发条件；日历事件与厂商待办的区别；跨 App 使用统计有哪些真实字段及特殊访问条件。
- **资料与方法**：S01–S08；先指定可借用手机、系统版本、target SDK 和安装来源。原生小实验用 Kotlin／Java 路径或经核实的框架桥接，不拿网页弹窗证明 Android 系统能力。
- **交付**：支持／未知矩阵及录屏／日志；通知允许／拒绝／撤销、锁屏／使用中／后台／终止／强制停止／重启与弱网结果；日历用户确认式导出 PoC 或可复现方案。UsageStats 先查权限和必要性，不默认开启。
- **通过条件**：服务受理、精确触发、终端展示和本人反馈分开；不以 Google Play 政策概括全部国内分发；不把日历事件当通用待办；不靠悬浮窗／无障碍绕行限制。没有条件的组合标未知。
- **依赖／输出给谁**：R04 的内容与隐私规则前置；跨 App 使用由 R01／R08 判断必要性再测试。给 R09 具体条件和失败证据，而非“安卓支持”。

### R06 · 穿戴与 BLE 接入选型

- **查什么**：已有设备能否通过获准平台、标准 GATT 或官方 SDK 读到所需字段；是历史记录还是低延迟流；广播具体包含什么。
- **资料与方法**：S08–S13、S24–S25；比较已有设备平台与公开协议传感器等至少两条路线。缺货／无账号时先查文档与工单，不盲目下单。
- **交付**：设备／固件、SDK／协议／语言、字段／单位、采样与同步、权限／账号、后台／断连、成本和撤销的选型卡；条件具备时，用自有或获准设备留脱敏样例。
- **通过条件**：厂商字段与实际记录对应；扫描不冒充读到健康值；不能把 Android／iOS SDK 写成 Python SDK，不能将某型号的 ECG 能力套给全部手表。华为当前资格页壳／检索证据需补官方确认，不概括“学生拿不到”。
- **依赖／输出给谁**：先由 R01／R09 明确数据能改善什么；R08 审健康数据用途；R07 接统一观测格式。只采自己／获准设备，不公开附近设备标识或轨迹。

### R07 · 雷达、IoT 事件与误报评估

- **查什么**：FDA2／BHA2 实际用途差异、安装与环境限制；观测如何校验、去重和保留不确定性；疑似跌倒的误报、漏报和不可用时间怎么统计。
- **资料与方法**：S14–S15、S17；先对 datasheet／固件／厂商不一致文案核查。优先合法数据、合成事件、可控回放或安全装置，不安排老人跌倒或诱发危险。
- **交付**：一个用途的一款设备选型建议，或明确暂不采购；最小事件 schema；重复、乱序、时钟错误、断网、抖动与解绑后重放的样例；事件级与每监测小时／天的误报评估方案。
- **通过条件**：设备观测、推断、自述和业务结果分层；不把存在写成身份／睡眠，不把心跳写成心梗判断；资料宣传参数不当实测。无设备与有设备增益可比较。
- **依赖／输出给谁**：与 R06 统一适配契约，异常升级先过 R08，R09 汇总可复现结果。采购和真实安装先获批准。

### R08 · 健康、隐私与紧急边界

- **查什么**：普通授权、敏感健康数据、明确 SOS、预授权疑似事件和法定紧急例外分别是什么；收集、分享、删除、退出与专业响应需要谁承担责任。
- **资料与方法**：S16–S18；引用原文，不用法规一句话推导“AI 判断危险就能绕过”。同时收集适用场景的专业意见；如果没有相应复核资源，明确不能开展的范围。
- **交付**：数据最小化与授权表、知情同意／退出要点、紧急分层草案、健康话术待审清单、误报和无响应处理方案、明确禁止承诺列表。列出是否需要隐私影响评估和进一步咨询的事项，不冒充最终法律意见。
- **通过条件**：不回复／晚睡／拒绝分享不被自动当紧急；付款者不是自动代理同意人；无通知不是安全证明；设备异常不能自行改药。任何外发敏感内容都有可解释的依据和接收范围。
- **依赖／输出给谁**：给 R01 真实招募要求、R02 保留／删除约束、R03 健康话术限制、R04／R07 紧急流程门槛。专业审查不由技术负责人单人代签。

### R09 · 综合评测、成本与亮点证据

- **查什么**：每个扩展是否增强主线，是否比已有工具更有用；单位家庭成本是否可承受；哪些宣传超出了实际证据。
- **资料与方法**：汇总全部包；对照原有微信／电话＋闹钟、通用助手／无长期记忆、纯摘要家庭视图，以及有／无设备。
- **交付**：可重跑的核心脚本、跨模块失败与权限用例、亮点—用户收益—证据对应表；成本模型分别记录语音、Agent／评测、主动消息、存储／推送、云与支持；本阶段保留／延后／不做建议。
- **通过条件**：合成、真实用户、模拟通知、实际终端和外部交流自报分账；未测写未知，未把部署和设备数当价值。实际付费与研究者提示下的使用也分开。
- **依赖／输出给谁**：不是代各模块补所有测试，而是要求每个主责提供可复核产物；结论提交团队决定，再更新正式产品与风险文档。

以下仅是排班示例，不假定实际人数：

- **约四位成员**：A 做 R01／R03 的产品调研，B 做 R02／R04 的规则和数据验证，C 做 R05 的手机能力验证，D 做 R06／R07 的条件性硬件与事件调研。R08 资料和 R09 证据整理按专长分担，并另落实专业审查；互相复核，不默认 D 采购或 B 包办实现。
- **约三位成员**：本阶段只启动用户／规则、手机能力、记忆／评测三条主线；雷达、跨 App 监控和更多设备暂不做。主动消息先用低风险原型验证。
- **更多成员**：可拆开 Android、BLE、雷达、家庭交互与评测，但保持一套事件、权限和证据口径。

如果原生手机、模型或专业能力暂缺，任务可以先交付官方证据、纸面状态图、合成样例和实验步骤，再安排学习／合作；不得把这些当作真实端到端完成。

## 六、阶段检查点与统一提交格式

| 检查点 | 看什么 | 未满足时怎样处理 |
|---|---|---|
| C0 认领与范围 | 主责／复核／日期、手机与设备库存、账号、预算、真实采集前置；是否启动硬件 | 不认领“共同负责”，不先购物或采集；按资源缩范围 |
| C1 资料与规则回收 | 官方来源、语言／平台／字段、用户问题、规则草案、未知与风险 | 补查或明确不采用；来源检索文本与正文核查分开，不凭营销页定型 |
| C2 小实验复核 | 合成／真机／设备标记、最小复现、失败与撤销、成本与条件 | 修正或暂停；本机可用不宣称全平台，单样例不宣称高准确率 |
| C3 主线与价值评审 | 全双工／记忆／提醒／授权家庭连接的协同、无待办价值、有无设备增益、真实试用前置 | 决定保留／延后／放弃；没有合规与安全条件不进入真实家庭使用 |

每包提交一份 Markdown，建议按以下结构；相关日志、脚本和数据脱敏后引用，不直接公开真实聊天／病史／家庭轨迹：

```text
工作包与主责／复核人：
要回答的用户问题／对应 Q 编号：
结论：可采用／条件性可用／待验证／暂不采用（不是“已支持”）：
依据：官方 URL、核查日期、SDK／协议／平台／语言／型号：
用户或对照证据：样本、方法、分母、反例和限制：
小实验：前置、版本、步骤、预期、实际结果、真实／模拟标记：
失败、未知、权限撤销、删除与恢复：
成本、许可／资格、隐私和安全影响：
对三个主亮点的增益，或为何不值得做：
下一项需团队决定的事项与检查日期：
```

**评审用一句话**：不是“我查到了这个功能”，而是“在这些条件下，它能为这个用户少做这一步；证据是什么，失败时怎样处理，值不值得投入”。
