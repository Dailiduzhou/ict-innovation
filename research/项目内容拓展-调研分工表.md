# 工作包目录 R01–R09

> 本文只定义"每个包要查什么、交什么、什么算通过"，不分人。谁做、做到哪一步见[三人分工](三人分工-资料查询与验证.md)；证据来源见[证据台账](项目内容拓展-证据索引.md)。
> 这是可认领的建议，不是九项立即开发，也没有预先分配姓名与截止日期。

## 一、三条规则

1. **分产物，不只分"前端／后端／硬件"。** 不懂 Agent 的人可以负责用户经历、交互走查、Android 权限、BLE、雷达、对照测试。每包一位主责＋一位不同的复核人；可以一人主责多包，但不能实现、评测、复现全压一人。
2. **分级验收。** 资料可用、账号可用、设备可用、项目构建、真机读数、端到端、用户价值，分别记。没条件时交明确阻塞与备选路线，不虚构成功。
3. **前置条件。** 真实访谈／录音／家庭试用先落实同意与退出；账号付费、设备购买、云资源创建先获批。医学与法律资料可由队友收集，但**不能把自行判断当专业批准**；未落实时只做低风险、合成或回放研究。

## 二、九个包

**R01 用户、竞品与付费价值** — 主责：愿意做产品分析的人
- 查：老人为什么第一次打开；愿不愿先对 AI 说原本对孩子说的话；微信＋电话＋闹钟哪里不够；谁安装、谁维护、谁付费。
- 交：一页用户情境与待验证假设；竞品矩阵（原有工具／通用 AI／老人陪伴／家庭协作）；老人独立与家庭参与两条价值路径；付费与反对理由。
- 不能：把市场规模当需求；把老人表达当噪声、把子女愧疚当支付理由、把赠送安装当留存。每条竞品事实带日期与来源。

**R02 记忆质量与评测门禁** — 主责：愿学模型评测／数据规则的人
- 查：候选与确认如何区分；新增、更新、冲突、去重、期限、删除、恢复；评测模型在哪里有用、在哪里与人一起犯错。
- 交：记忆字段与写入规则草案；审查 rubric；合成且人工标注的用例（否定、改口、时间范围、错人、敏感内容、删除后重处理、跨用户隔离）；规则／单模型／加审查三方案的质量-耗时-费用对比设计。
- 不能：用总分掩盖错误共享、误用药、跨用户污染；不写"永不劣化"；删除内容不因回滚复生。

**R03 主动关怀与消息策略** — 主责：产品／交互，配合 API 调研者
- 查：天气、衣物、可信季节信息、子女真实关切、既有用药安排、不适回访、未处理卡片、长期未互动、沟通风格，各自如何触发与停止。
- 交：按消息类型列触发依据、对象、来源与有效期、渠道、安静时段、频率、未回应处理、取消方式；若选天气 API，补语言／协议、认证、账号、配额、费用与归因。
- 不能：无答复当同意；普通关怀与用药计划混用同一套节流；伪造子女留言、个人疾病预测、补服建议。

**R04 分享、家属建议与多人协作** — 主责：产品状态流程／前后端协作
- 查：保留、执行、分享、求助是否分权；家属提议何时生效；接手与转让如何确认；撤销影响谁；空近况与无待办是否仍有价值。
- 交：权限表与状态迁移表；分享确认／家属建议／接手转让／老人反馈的界面或纸面脚本；确认与拒绝的误解记录。
- 不能：目标亲属未获权限先泄露详情；转让未接受就说已接手；只对明确求助办结。现有原型"换水安排出现在子女话题"的授权缺口须给修正方案。

**R05 Android 通知、日历与使用统计** — 主责：愿做手机原生小实验的人
- 查：通知、全屏意图、精确闹钟的权限与分发条件；日历事件与厂商待办的区别；跨 App 使用统计的真实字段与特殊访问。
- 交：支持／未知矩阵＋录屏或日志（允许、拒绝、撤销、锁屏、使用中、后台、终止、强制停止、重启、弱网）；日历用户确认式导出 PoC 或可复现方案；UsageStats 先判必要性，不默认开启。
- 不能：把服务受理当终端展示、当本人反馈；用 Play 政策概括全部国内分发；把日历事件当通用待办；靠悬浮窗或无障碍绕行。

**R06 穿戴与 BLE 接入选型** — 主责：BLE／嵌入式方向
- 查：已有设备能否经获准平台、标准 GATT 或官方 SDK 读到所需字段；历史记录还是低延迟流；广播究竟含什么。
- 交：至少两条路线比较；一款候选的设备／固件、SDK 或协议、语言与平台、字段与单位、采样与同步、权限与账号、后台与断连、成本与撤销的选型卡；条件具备时留脱敏样例。
- 不能：扫描冒充读到健康值；把 Android／iOS SDK 写成 Python SDK；把某型号 ECG 能力套给全部手表；把某条检索证据当成"学生拿不到"或"已获准"。

**R07 雷达、IoT 事件与误报** — 主责：传感器／事件处理方向
- 查：跌倒型与呼吸心跳型套件的用途差异、安装与环境限制；观测如何校验、去重、保留不确定性；疑似跌倒的误报、漏报与不可用时间如何统计。
- 交：一个用途的一款设备建议，或明确暂不采购；最小事件 schema；重复、乱序、时钟错误、断网、抖动、解绑后重放的样例；事件级与每监测小时／天的误报评估方案。
- 不能：把存在写成身份／睡眠，把心跳写成心梗；把宣传参数当实测；安排老人跌倒或诱发危险。

**R08 健康、隐私与紧急边界** — 主责：资料严谨的同学＋**待落实的外部专业复核**
- 查：普通授权、敏感健康数据、明确 SOS、预授权疑似事件、法定紧急例外分别是什么；收集、分享、删除、退出与专业响应的责任归属。
- 交：数据最小化与授权表；知情同意／退出要点；紧急分层草案；健康话术待审清单；误报与无响应处理；明确禁止承诺列表；是否需要隐私影响评估。
- 不能：把不回复／晚睡／拒绝分享当紧急；把付款者当自动代理同意人；把无通知当安全证明；让设备异常触发改药。**技术负责人不能单人代签。**

**R09 综合评测、成本与亮点证据** — 主责：协调／测试／复现方向
- 查：每个扩展是否增强主线、是否比已有工具更有用、每户成本是否可承受、宣传是否超出证据。
- 交：可重跑的核心脚本；跨模块失败与权限用例；亮点—收益—证据对应表；成本模型（语音、Agent／评测、主动消息、存储／推送、云与支持）；保留／延后／不做建议。
- 不能：替各包补所有测试；把部署和设备数当价值；把研究者提示下的使用与真实付费混为一谈。

## 四、检查点与提交格式

| 检查点 | 看什么 | 未满足怎么办 |
|---|---|---|
| C0 认领与范围 | 主责／复核／日期、手机与设备库存、账号、预算、真实采集前置；是否启动硬件 | 不认领"共同负责"，不先购物或采集；按资源缩范围 |
| C1 资料回收 | 官方来源、语言／平台／字段、用户问题、规则草案、未知与风险 | 补查或明确不采用；检索全文与正文分开记 |
| C2 小实验复核 | 合成／真机／设备标记、最小复现、失败与撤销、成本与条件 | 本机可用不宣称全平台；单样例不宣称高准确率 |
| C3 主线与价值评审 | 三条亮点的协同、无待办价值、有无设备增益、真实试用前置 | 保留／延后／放弃；无合规与安全条件不进真实家庭使用 |

每包提交一份 Markdown，格式见[证据台账第六节](项目内容拓展-证据索引.md#六采用任何外部依赖前另填一份不以本表代替实测)；日志、脚本与数据脱敏后引用，不公开真实聊天／病史／家庭轨迹。

**评审只用一句话**：不是"我查到了这个功能"，而是"在这些条件下，它能为这个用户少做哪一步；证据是什么，失败时怎么办，值不值得投入"。
