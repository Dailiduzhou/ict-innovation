**铁律**：本项目只有 1 人有后端经验，而 [R-47](../ideas/12-风险与待验证.md) 正是"实现、测试、文档、联调压在一人"。所以甲的每份产物要有乙或丙做**可复现复核**（不是"看过"），乙丙的产物由甲复核技术口径。**没有复核人的包不开工。**

**人数的取舍**：三人阶段只启动「用户与规则 / 手机能力 / 记忆与评测」三条主线。雷达、跨 App 使用统计、多品牌穿戴**只做零成本资料与自有设备实验，不采购、不进主线**。IoT 同学的优势要发挥，但不能用设备数量换掉主线证据。

## 四、各包做什么（只写要点，通过条件见工作包目录）

**甲 · M**
- **M1**：记忆字段与写入规则（来源、表达时间、适用时间、状态、修订关系）＋审查 rubric ＋合成且人工标注的用例（否定、改口、时间范围、错人、敏感内容、删除后重处理、跨用户隔离）＋规则／单模型／加审查三方案的质量-耗时-费用对比。只写不跑，等账号批准。
- **M2**：事件契约（`event_id`、设备／固件／协议、`observed_at`、`received_at`、时间质量、类型／值／单位、有效性、绑定依据、真实或模拟）＋提醒与请求的状态机 ＋"重试不产生两条提醒／两次发送"的用例。与丙共用一份 schema，不各写一套。
- **M3**：和风 v1 真实调用记录（城市、时间、字段、错误码）＋成本模型骨架。凭据只在服务端；疾控当前无稳定 API，按人工审核选题处理。

**乙 · P / S1 / S3**
- **P1（最先做）**：一台真机的矩阵——型号／系统／target SDK／安装来源／权限状态 × 允许、拒绝、事后撤销、锁屏、使用中、后台、进程被杀、强制停止、重启、弱网。把"已保存／调度触发／渠道受理／终端展示／本人反馈"分开记；国内厂商渠道单列一列。
- **P2**：先做"确认后导出为系统日历事件"，再评估双向同步；记事件映射、时区、修改删除来源、双提醒冲突。跳转编辑页只记"待用户完成"。
- **P3**：JPush（Android／iOS／HarmonyOS，HTTP Basic，无浏览器 Web Push）、HMS Push 账号与应用条件、荣耀独立路径、厂商配置要求；标明"服务受理 ≠ 有人看到"。衔接 [08](../ideas/08-外部依赖核查.md) 已核部分，不重复。
- **P4**：UsageStats 的特殊访问授权、字段边界、分发政策；产出"值不值得做"一页，倾向不做。
- **S1**：经同意的访谈／概念测试——具体经历、反例、第一次为什么打开、谁帮安装、与微信＋电话＋闹钟比哪一步值得改。没条件时交招募与提纲，不编结果；子女不能代老人同意。
- **S3**：按消息类型（天气衣物、季节提示、子女真实留言、既有用药计划、不适回访、未处理卡片、长期未互动、沟通风格）列触发依据、来源与有效期、渠道、安静时段、频率、未回应、取消方式。

**丙 · D**
- **D1**：Health Connect（含 Changes token 与 BLE 伴生低延迟）、Wear OS（Passive／Measure／Exercise 的适用差别）、Polar（支持型号 × 字段）、华为（待补证）四条路线比较；每个指标落到具体型号；标明 Android Kotlin／iOS Swift 路径，**不是 Python 后端 SDK**。缺货无账号时只交文档与工单，不盲下单。
- **D2**：MR60FDA2（跌倒）与 MR60BHA2（呼吸心跳）用途差异、安装与供电、多人宠物环境影响；**页面型号与范围参数口径不一致处必须核 datasheet 或工单**。
- **D3**：最小事件 schema ＋ 重复、乱序、时钟漂移、断网、抖动、解绑后重放的样例与预期 ＋ 事件级与每监测小时／天的误报评估（含分母与不可用时间）。无数据要表达为"不可用"，不当"没人活动"。

**S4 分块**：甲查数据最小化／删除／影响评估（个保法 13、18、28、29、55）；乙查手机权限与分发政策的真实限制；丙查设备用途与来源可信度。产出授权与数据最小化表、同意与退出要点、紧急分层草案、禁止承诺清单。

## 五、启动顺序

**第一批（可同时开，两到三周回收）**
1. 乙 P1 —— 一台真机的通知／精确闹钟矩阵（最便宜、最快出真证据，直接决定主线可信度）。
2. 甲 M1 —— 记忆规则 v0.1 ＋ 合成用例集（只写不跑）。
3. 丙 D1 文档 ＋ D3 schema 草案（零成本，且是 M2 的前置）。
4. 乙 S1 前置 —— 提纲、同意流程、招募渠道（**只准备，不采集**）。

**第二批**：甲 M2（要 D3 字段）、乙 P3、乙 S3、甲 S2。
**第三批（有条件才开）**：乙 P2、甲 M3（需费用批准）、丙 D2。

**本阶段明确不启动**：任何设备采购、真实老人录音与家庭试用、跌倒／心梗真实场景实验、跨 App 长期监控、多品牌穿戴适配。这些要过 C0（资源、预算、同意、专业复核）。
