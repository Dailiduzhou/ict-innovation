# 03 · 讲故事

> 人物、对话和时间均为虚构场景，用于表达价值与设计 Demo，不是真实用户研究或已交付功能。产品方向与待验证设计的区别见 [目录说明](README.md)。

## 一、主叙事

> **AgeGuard 是能自然交流、记住个人生活并主动提供帮助的老人语音生活助理；在老人授权下，它也帮助子女理解父母、延续交流和参与具体帮助。**

技术核心是后端全双工语音与并行 Agent Loop。用户感受到的是：说话可以打断、补充和改口；重要信息跨会话仍然有用；确认过的安排能在以后得到提醒。

手机就能使用。硬件是可选情境数据源，不用“购买两个盒子”解释产品，也不以设备数量证明创新。

## 二、从什么矛盾开场

部分老人很期待与人交流，会分享很长的语音；子女在忙碌时可能听不完，也很难记住其中的生活细节。问题不只是信息太多，更是两代人的表达意愿与可投入时间不总是匹配。

不能只问“怎样把长语音变短”，还要问“怎样保留父母真正想分享的东西，让下一次交流更容易”。

> **不是替子女听完父母的话，而是帮助子女更容易听懂，也更容易接着聊。**

这是价值主张，尚不是已经证明的效果；不宣称所有老人都话多或所有家庭都需要介入。

## 三、一段闲聊，三种价值

陈阿姨用手机和助理聊起养鱼：

> “今天鱼又活泼起来了，前两天我还担心呢……你小时候也爱站这里看。周六十点提醒我照原来的安排给鱼缸换水。对了，鱼粮快没了，想请小林回来时带一袋。”

不要只讲成“识别了买鱼粮任务”。这段话包含：

| 内容 | 系统的帮助 | 不应越过的边界 |
|---|---|---|
| 正在关心的生活 | 记住养鱼背景与这次近况，保留来源 | 不把担心鱼推断为心理诊断 |
| 家庭回忆 | 在愿意分享时保留原话，成为子女联系的话题 | 不默认共享全部谈话 |
| 自己的安排 | 确认时间后创建提醒，可查询、调整、取消 | 不因习惯自行规定换水方法或频率 |
| 具体求助 | 确认接收人与内容，创建鱼粮请求 | 不自动广播给所有亲属 |

## 四、完整故事：先生活，再连接，最后协助

### 第一幕：有人愿意听，不要求每句话都有用

陈阿姨用手机聊天，说鱼、花和家里的小事。她可以插话、补充和纠正；助理不急着把每段话转换成任务，也不以“提取不到事项”结束闲聊。

后台 Agent 整理允许保留的重要信息，形成有来源的记忆候选。系统可以先回应“我听到了”，但只有持久化成功后才明确说安排已保存。

### 第二幕：聊过的事情，下次仍然记得

另一次会话，她问“上回鱼缸的事还记得吗？”系统在授权和保留范围内召回背景。她确认周六十点提醒，任务可靠保存。

到了提醒时间，她说“昨天已经弄好了”。系统关联到这一次安排，不重复催促，也不自动取消以后的全部提醒。

### 第三幕：子女看到的不只有任务

在母亲授权下，小林看到少量近况和母亲愿意分享的原话。准备联系时，她可以回顾：“妈妈最近在关心什么？”

系统提示鱼的近况及相关回忆，不生成孝心分数，不假装知道外部电话。小林自然问起：“你那几条鱼后来怎么样了？”

电话或微信仍然可以是原有工具；AI 提供上下文，不替代真实联系，也不自动认定外部通话已完成。

### 第四幕：关心可以双向流动

小林主动留下一句真实回应：“我还记得小时候看鱼，周日回来一起看看。”系统明确发送者，在母亲允许的方式下转达。

母亲感受到的不是“资料被孩子查阅”，而是“分享有人接住”。这是希望验证的体验，不把它写成既得成果。

### 第五幕：确实需要办事，才用事项闭环

鱼粮请求经确认后进入“需要你参与”。小林可以答应、协商时间或说明做不了；后台记录状态，前台使用家庭可理解的表达。

没有待办时，近况、话题与真实回应仍有价值。接手和办结是协助能力，不是整个家庭关系的度量。

### 可选一幕：传感器补充背景

接入获准的人体存在传感器或智能开关后，可在明确观测能力内改善互动时机、减少重复询问。没有硬件，前五幕也应成立；传感器不能证明本人身份、已完成家务、已服药或当前安全。

## 五、介绍口径

### 一句话

> AgeGuard 通过自然语音交流记住老人的生活与安排，在合适的时候提供提醒，并在授权下帮助家人更好地了解彼此、保持联系。

### 30 秒

> 有些老人很想分享生活，子女却未必有时间逐条听完长语音。AgeGuard 让老人直接用手机自然交流，在对话同时由后台 Agent 整理重要信息，形成可纠正的个人长期记忆，把确认过的安排变成后续提醒。在老人授权下，子女看到的不只是待办，还有值得听的近况、可以接着聊的话题和父母愿意分享的原话。明确需要帮助时，再形成可跟进事项。

### 技术补充

> 全双工语音处理自然交流与打断，后台 Agent Loop 处理记忆、检索、提醒和共享候选。持久化、授权、任务版本与调度由业务服务控制。自建或其他品牌硬件只提供可选数据，具体能力以实际接入验证为准。

## 六、五分钟 Demo 的重点

| 顺序 | 展示 | 验证什么 |
|---|---|---|
| 1 | 手机自然闲聊，中途补充或纠正 | 全双工与并行处理，不依赖专用盒子 |
| 2 | 展示带来源的记忆，下次会话召回及纠错 | 不是一次性摘要，也不是模型凭空记得 |
| 3 | 创建、查询和取消一个生活提醒 | 受控副作用、持久化、版本与失败反馈 |
| 4 | 经授权展示近况、原话和联系前回顾 | 子女端在没有任务时仍有价值 |
| 5 | 子女发送真实回应，再展示一个明确求助 | 双向关系与事项能力分开 |
| 6 | 拒绝共享、撤销或保存失败中的一条 | 展示边界，不只演成功路径 |

定时触发如使用测试时钟、加速或回放必须显著标识。未真实联系的电话不算已发生，模拟通知不算送达，分段语音不冒充全双工。可选设备演示单独标注，不能取代核心软件证据。

## 七、不要这样讲

| 偏差 | 应改成 |
|---|---|
| 老人长语音都是需要清理的噪声 | 同时保留信息与关系价值，验证是否真的减负 |
| 把所有闲聊变成子女工单 | 分享、联系邀请、明确求助分别处理 |
| AI 替子女尽孝、自动生成关心 | 提供上下文，转达真实回应，不冒充本人 |
| 家属随时掌握老人全部情况 | 老人控制共享，系统只知道实际采集到的内容 |
| 记忆永久保存所以可靠 | 存储、理解、恢复、纠错、删除分别验证 |
| 语音盒和药盒是产品主角 | 手机即可使用，可选硬件增加情境信息 |
| 全双工以后再做，先用录音证明核心 | 分段录音可开发或降级，但不算核心目标完成 |
| AgeGuard 保证安全、发现所有危险 | 日常生活辅助与家庭连接，不替代监护和急救 |

## 八、落点

> **老人说过的重要事情，不随一次对话结束就消失；它们在本人可控制的范围内被记住，在适当的时候得到帮助，也让家人下一次交流更有上下文。**

减轻的是整理、寻找和重复确认的负担，不是减少真实交流。评测要同时观察子女负担与老人感受，不能只报告省了多少听语音的时间。
