# 02 · 需求

## 一、核心问题

> 老人愿意分享的生活信息散落在闲聊里，重要安排容易遗忘；子女不一定有时间逐条听完，却仍希望理解父母、维持真实联系。

长语音同时承载信息和关系。产品应减少整理、重复交代和寻找上下文的负担，不以减少老人与子女交流为成功。

用户侧的价值链是：

```text
自然交流 → 记住有用背景 → 到时提供帮助
                     └→ 经授权保留值得分享的近况和话题 → 支持真实家庭交流
                                                       └→ 明确求助才进入事项跟进
```

实现主线是全双工语音与后台 Agent Loop 并行；它们不是两个互不相关的卖点，而是让“聊天时不被办事打断，聊过的事情以后仍有用”的机制。

## 二、需求分层

| 需求 | 典型表达 | 应交付的体验 |
|---|---|---|
| 自然交流 | “等等，不是明天，是后天……” | 可插话、补充、改口；闲聊不必产生任务 |
| 跨次记忆 | “上次说的那个鱼缸……” | 有来源的个人长期记忆，跨会话可检索、纠正与删除 |
| 主动帮助 | “周六十点提醒我按原来的安排给鱼缸换水。” | 受控创建定时任务，可靠保存，按计划执行，支持反馈与取消 |
| 家庭连接 | “这事也想和女儿说说。” | 在授权范围内分享近况、原话与话题，支持真实回应 |
| 具体协助 | “鱼粮快没了，请她周末带一袋。” | 澄清对象与请求，形成可以接手和反馈的关怀事项 |
| 情境增强 | 愿意接入人体存在传感器或智能开关 | 减少重复输入，改善互动时机；无硬件也可使用 |

## 三、个人长期记忆：不只是摘要，也不是无限留存

“全局记忆”指该用户跨会话可用的个人记忆，至少区分：

- **背景与偏好**：兴趣、称呼、交流偏好、普通提醒的安静时段。
- **习惯与候选规律**：有时间范围、来源和不确定性，不因一次表达变成永久画像。
- **已确认安排**：提醒计划及版本；习惯不自动等于执行计划。
- **关系上下文**：家庭回忆、愿意分享的话题、系统实际知道的约定。
- **进行中的事情**：本次提醒反馈、联系邀请、明确求助及其变化。

可靠性有三个独立要求：

1. **保存可靠**：持久化、重试幂等、恢复和备份策略；不能只存于易失会话。
2. **理解可靠**：有来源、区分候选与确认，允许纠错，不把摘要写成新事实。
3. **共享合适**：个人记忆与家庭可见内容分离；重要不等于应当共享。

音频、转写、记忆、摘要、索引和审计分别定义保留期限。删除或撤销需作用于派生内容；不能让后台整理从旧对话重新恢复已删除记忆。可靠存储不等于永久保存一切。

## 四、主动提醒：从交流走向未来帮助

- Agent 可从生活背景提出提醒建议；具体执行依赖本人确认或明确有效的预授权规则。
- 低风险生活提醒减少重复设置，但不擅自把“平常这样做”变成永久任务。
- 一次已完成不自动取消以后所有安排；临时改时间不自动改写长期习惯。
- 提醒创建、计划持久化、渠道受理、终端展示与本人反馈分开记录。
- 用药提醒依据已核对的现有安排，不自行推导剂量、补服、疗程或改药。
- 普通手机后台和网络存在限制；产品须说明已验证范围，不能声称必达或急救级可靠。

## 五、子女端：先看见生活，再延续交流，最后处理请求

### 5.1 最近的生活

少量经授权的近况，带来源与时间，可查看老人愿意分享的原话片段。没有新内容不凑日报，不把普通兴趣或重复提及自动解释为心理异常。

摘要帮助快速理解，原话保留人的声音。原话片段也受授权和保留期限约束；抽取不能断章取义，不使用合成父母声音代替真实表达。

### 5.2 下次聊什么

联系前回顾父母近期关注的事、系统内已知约定和上次未完的话题。输出是可选线索，不是自动问候模板，不假装读取微信聊天或知道外部通话内容。

例如：“妈妈前几天一直关注鱼的状态，今天说好些了，可以问问后来怎么样。”这是回顾来源，不是替子女判断母亲情绪。

### 5.3 需要你参与

只有明确请求才有接手、时间协商和处理反馈。前台使用“妈妈想请你……”等自然表达，后台保留严谨状态与失败恢复。

生活分享不要求已读打卡；联系邀请可以回应、婉拒或约时间，不默认进入必须办结的工单队列；通话发生不等于关怀满足。

### 5.4 双向的真实回应

子女可以主动留下近况、文字或语音，回应父母的一件小事。系统在适当且获准的方式下转达，明确真实发送者，不代发、冒充或编造“孩子已经看过”。

首版以真实留言为主；照片等形式按需求扩展，不先建设完整社交平台。联系和通话可继续使用家庭已有工具。

### 5.5 不是三个信息队列

首页首先帮助回答“父母最近在过怎样的生活”。话题回顾服务准备联系的时刻，明确请求才进入处理流程。不以待办数、红点、日报阅读率或回复速度制造负担。

判断标准：**今天没有待办，子女仍可能因了解近况、准备联系或留下一句真实回应而使用。** 不要求每天打开，更不把每日活跃等同于关系改善。

## 六、隐私、情境与价值边界

- 私人记忆不默认成为子女端内容；既有类别授权与逐次确认结合，敏感内容、新接收人和扩权更谨慎。
- 老人拒绝分享，不发送“有一条不愿分享的内容”等旁路提示；已看见的信息无法承诺收回。
- 传感器只提供具体观测：区域存在、开关、容器开合等不证明身份、情绪、睡眠、吞服或危险。
- 对话摘要不能代替医学判断；普通提醒与亲属响应不替代专业照护或急救。
- 目标是减少信息处理负担，同时保留表达意愿和真实交流；不是用 AI 消除子女倾听的责任。

## 七、首版优先与验证

首版核心：手机全双工对话、并行 Agent、个人长期记忆及纠错、受控定时提醒、近况＋来源、联系前回顾、真实留言、明确求助及授权。

可选扩展：人体存在传感器、智能开关、自制节点、药盒和语音盒；逐型号验证，不作为核心验收前提。

需验证：对话是否自然、重要信息是否准确保留、存储和任务是否可靠、子女理解负担是否降低、交流是否更容易延续、老人是否仍感到自主且被听见。具体测试见 [评测方案](../ideas/10-评测方案.md)，不预填效果数字。
